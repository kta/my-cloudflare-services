# 典拠（Tenkyo）— 予算とキャパシティ設計

**結論から: 追加の金銭コストは 0 円である。** 支払うのは**ディスクと時間**であり、それが実質的な予算である。
本書の数字は推測ではなく、**このリポジトリのコマンドで誰でも再現できる実測値**である。

## 2. 実測値（再現手順つき）

計測環境: macOS (Apple Silicon) / Node 26.8.1 / `node:sqlite` SQLite 3.53.4 / WAL・`synchronous=NORMAL`。

```sh
cd packages/patent-corpus
node src/cli.ts synth --db /tmp/budget.db --count 2000 --seed 11
node src/cli.ts embed --db /tmp/budget.db --dim 768
node src/cli.ts stats --db /tmp/budget.db
```

| 指標 | 実測値 |
|---|---|
| 合成した公報 | 2,000 件 / 124,332 段落（**62.2 段落/公報**） |
| 本文の分量 | **6,581 文字/公報**（106 文字/段落） |
| 取り込み速度（合成 + 段落分割 + bigram 生成 + FTS5 索引 + 取引） | **341 公報/秒** |
| DB サイズ（全文 + FTS5 索引） | 95.6 MB → **46.7 KB/公報** |
| 検索「瞳孔」（68,544 件ヒット） | Node の起動込みで 189 ms（起動が約 120 ms） |
| 検索「瞳孔 中心」（23,127 件） | 起動込み 148 ms |
| 埋め込み（deterministic・768 次元） | **9,642 チャンク/秒** |
| 埋め込み後の DB | 277.7 MB → **1.5 KB/チャンク**（int8 768B + 1bit 96B + 行の付帯） |

> **以前の版との差**: この文書の初版は 1,714 公報/秒・27.2 KB/公報 と書いていた。
> それは合成データが 1 公報あたり 3,700 文字だった時点の、別のベンチ用スクリプトでの値であり、
> **CLI からは再現できなかった**。合成データを実際の公報に近い分量へ直し、
> かつ取り込みを取引（BEGIN IMMEDIATE）で囲んだ結果、速度は落ちて容量は増えた。
> **速度を落としたのは正しさのためである**（取引が無いと、途中で失敗したときに
> 実在する典拠が「却下」に化ける）。

## 3. 計算式（件数を入れると量が出る）

実測は 1 公報 = 6,581 文字である。実際の日本語の公開特許公報、特にソフトウェア分野では
**1 公報あたり 10,000〜20,000 文字**が一般的とされる。
`[要確認: 実データ到着後に `corpus stats` で実測し、本節の係数を置き換える。]`

以下は **1 公報 = 12,000 文字（実測の 1.82 倍）** を仮定した見積りである。

```
層1（書誌のみ・全件）  = 公報数 × 1.5 KB
層2（全文 + FTS5 索引）= 公報数 × 46.7 KB × (平均文字数 / 6,581)
層3（意味ベクトル）    = 公報数 × 段落数 × 1.5 KB
取り込み時間           = 公報数 / (341 / (平均文字数 / 6,581))  秒
埋め込み時間           = 公報数 × 段落数 / スループット(チャンク/秒)  秒
```

| 規模 | 層1 | 層2（12,000字） | 層3（62段落・768次元） | 合計 |
|---|---|---|---|---|
| 10 万公報 | 0.15 GB | **8.5 GB** | **9.3 GB** | 約 18 GB |
| 100 万公報 | 1.5 GB | **85 GB** | **93 GB** | 約 180 GB |
| 500 万公報 | 7.5 GB | **426 GB** | **465 GB** | 約 900 GB |

**16TB の HDD に対して、500 万公報の全文索引とベクトルを入れても約 900GB（6%）**である。
容量は制約にならない。制約は時間である。

ベクトルは **float32 を保存しない**。int8（次元数 + スケール）と 1bit（次元数 / 8）だけを持つ。
float32 は int8 比で 4 倍のディスクを食い、検索順位への影響はほとんど無い。
次元を 768 から 256 に落とせば層3 は約 1/3（500 万公報で 155GB）になる。

| 規模 | 取り込み（実測ベース） | 埋め込み `deterministic`（純JS・実測） | 埋め込み `ollama` + bge-m3（**未実測の推定**） |
|---|---|---|---|
| 10 万公報 | **9 分** | **11 分** | 約 22〜57 時間 |
| 100 万公報 | **1.5 時間** | **1.8 時間** | 約 9〜24 日 |
| 500 万公報 | **7.4 時間** | **8.9 時間** | 約 45〜120 日 |

`ollama` の列だけが推定である（30〜80 チャンク/秒を仮定）。
`[要確認: ollama を導入した時点で実測し、この列を置き換える。]`

## 4. この見積りから出る運用方針

1. **全文の取り込みと FTS5 索引は、最初から全件やる。** 500 万公報で 7〜8 時間、426GB。
   これで「分類コード + 全文検索」による調査は**受領データの全範囲**に対して可能になる。
   実務の第一級の道具がいきなり全範囲で使えるのは、この設計の一番大きな利点である。
2. **意味ベクトルは段階的に広げる。**
   - 第1段: 案件の技術分野の IPC サブクラス（例 `G06F3/01`）→ 数千〜数万公報 → 数時間
   - 第2段: 関連サブクラスへ拡張
   - 第3段: 全件（連続実行。夜間に進める前提）
3. **`deterministic` 埋め込みは捨てない。** 意味は捉えないが、全件に即座にかけられ、
   決定的（同じ入力→同じ出力）なので、回帰テストとベースラインとして常に有効である。
   UI にはモデル名（`deterministic:768`）が出るので、利用者が取り違えることはない。
4. **どの範囲が意味ベクトル済みかを、検索結果に必ず添える。**
   見ていない範囲を「無かった」と誤読させないため。

### 4.1 やらないと決めたこと（実測に基づく）

**1bit 量子化による粗い絞り込みは実装しない。** 一度作ったが、実測で
**recall@10 が 27〜40%**（真の上位の 6〜7 割を落とす）だったので削除した。

```
dim=768 総チャンク 5,318  幅 100  → recall@10 = 27%
                          幅 500  → recall@10 = 53%
                          幅1000  → recall@10 = 90%（総数の 19% まで残してようやく）
```

二段検索（FTS5 と分類コードで数千件に絞ってから）が前提なので、
候補集合を総当たりしても速度は足りる。先行技術調査で 6 割を静かに落とす機能は、
速くても製品に載せてはいけない。数百万チャンクを分類コード無しで横断する用途には
別の手法（本物の ANN）が要るが、**まだ作っていない。作っていないものを使えるように見せない。**

## 5. リスクと、それにいくら払うか

| リスク | 影響 | 対処 | 追加コスト |
|---|---|---|---|
| PDF にテキストレイヤが無い（OCR 必要） | 全文が取れない | インポータは **TSV（書誌）→ XML（全文）→ PDF（フォールバック）** の 3 系統。XML が併存すれば PDF を触らない | 0 円（Tesseract / macOS Vision は無料）。ただし OCR は 1 公報あたり数秒 → 全件は非現実的なので、必要時のみ |
| バルクデータの二次利用が不可 | **外販ができない** | 自己利用の範囲で作り切る。外販は規約確認後に判断 | 0 円（ただし事業計画に直撃するので最優先で確認） |
| `ollama` の埋め込みが遅すぎる | 意味検索の範囲が狭まる | 二段検索なので**意味ベクトルが無くても調査は成立する**（FTS5 + 分類コードが第一級）。ベクトルは上積み | 0 円 |
| HDD 故障 | コーパス喪失 | **コーパスは派生物**。受領媒体と `import_batches` の記録があれば再構築できる（500 万公報で 7〜8 時間） | 0 円 |
| 案件データ（発明・典拠・ドラフト）の喪失 | **取り返しがつかない** | D1 のローカル SQLite を定期的に別ディスクへ複製する | 0 円 |

**最後の行が本当の予算である。** コーパスは何度でも作り直せるが、
人間が積み上げた典拠の検証結果と明細書ドラフトは作り直せない。
ここのバックアップだけは手を抜かない。
