# 典拠（Tenkyo）を動かす

特許の先行技術調査と明細書の下書きを、公報の原文に一つずつ突き合わせながら進める作業机。
**ローカルで完結する**（Cloudflare へデプロイしない）。追加の金銭コストは 0 円
（`docs/patent/BUDGET.md`）。

## 何がどこで動くか

```
プロセス1  services/patent_research   :5177   SPA + API（1 つの Worker）
                                              D1 = 案件・典拠・ドラフト（作り直せない）
プロセス2  packages/patent-corpus     :8899   コーパスサイドカー（公報の書誌・全文・索引）
                                              corpus.db（派生物。作り直せる）
プロセス3  Claude Code のスキル        手動    分析（検索・特許性・ドラフト）
```

Worker はコーパスを直接読まない（workerd にファイルシステムが無い）。
`x-internal-key` 付きの HTTP で問い合わせる。

## はじめての起動（実データが無くても動く）

```sh
# 1. 合成コーパスを作る（実データが届く前でも全機能を触れる）
make corpus/synth COUNT=500

# 2. コーパスサイドカーを起こす（このターミナルは開けたままにする）
make corpus/serve

# 3. 別のターミナルでアプリを起こす
make db/migrate/local      # 初回のみ
make dev/patent_research   # http://localhost:5177
```

作業空間の名前（何でもよい。例 `tenkyo`）を入れて開く。

## 使う順番

1. **発明を書く** — 課題・手段・効果・実施形態。ここに書いたものは**未出願の秘密**で、
   外部 LLM への送信は既定で切ってある。
2. **構成要件** — 請求項の文を貼って「構成要件に割る」。機械的に割るだけなので必ず人が直す。
   **調査の単位は文献ではなく構成要件である。**
3. **先行技術検索** — 構成要件を選んで検索する。実行した検索式・ヒット件数・公開日不明の件数が
   そのまま記録に残る（調査報告書になる）。当たった段落を「典拠に積む」。
4. **クレームチャート** — 積んだ典拠が検印（済・未・却）付きで並ぶ。
   - **済** = 引用文が公報のその段落の原文に実在することを機械が確かめた
   - **却** = 原文と食い違った。台帳から降ろされ、**AI の主張と実際の原文が左右に並んで**残る
   - **未** = まだ確かめられていない（コーパスに届かない等）
   照合を通った典拠だけ、人間が「開示を認める」ことができる。
5. **特許性の判断** — 新規性は単一文献、進歩性は主引用→副引用→動機付けの 4 類型→有利な効果→阻害要因。
6. **明細書ドラフト** — 施行規則の見出しごとに Markdown で書く。要約は 400 字で警告が出る。

## 分析を Claude Code に任せる

画面の各所から「仕事」を積み、**別のターミナルでスキルを起こして**拾う。
画面が勝手に走らせないのは、未出願の発明が動くからである。

```sh
claude "/patent-search"          # 構成要件ごとに検索式を組み、典拠を積む
claude "/patent-assess"          # 照合済みの典拠だけを根拠に特許性を論じる
claude "/patent-draft"           # 明細書の下書きを起こす
claude "/loop 30m /patent-search" # 間隔をあけて拾い続ける
```

## 実データ（受領媒体）が届いたら

**仕様書を読む前に、実物に形を聞く。**

```sh
make corpus/probe PATH_TO_MEDIA=/Volumes/JPO
```

拡張子の分布・ディレクトリの深さ・TSV のヘッダ・XML のタグ・**PDF にテキストレイヤがあるか**を
報告する。その出力を見てから、`packages/patent-corpus/src/adapters/tsv.ts` の
`DEFAULT_TSV_MAPPING` と `adapters/xml.ts` の `DEFAULT_XML_MAPPING`（どちらも
`unverified: true` の仮置き）を実物に合わせて確定させる。

```sh
cd packages/patent-corpus
node src/cli.ts import-tsv --db .data/corpus.db --file /Volumes/JPO/master.tsv --media HDD-01
node src/cli.ts import-xml --db .data/corpus.db --dir  /Volumes/JPO/xml       --media HDD-01
node src/cli.ts stats --db .data/corpus.db
```

取り込みの順序は **TSV（書誌）→ XML（全文）→ PDF（どちらも無い場合のフォールバック）**。
PDF を主経路にしない。

## 意味検索を足す（任意）

既定の埋め込みは追加インストール不要だが**意味は捉えない**（語の重なりを測るだけ）。
画面にモデル名が出るので取り違えることはない。意味ベクトルが要るなら:

```sh
# ollama を入れて bge-m3 を落としておく
node src/cli.ts embed --db .data/corpus.db --provider ollama --model bge-m3 --dim 1024 --ipc G06F3
```

所要時間は `docs/patent/BUDGET.md` の表を見る。**全件は数ヶ月かかる**ので、
案件の技術分野から段階的に広げる。全文検索と分類コードは最初から全範囲で使えるので、
意味ベクトルが無くても調査は成立する。

## 大事な約束

- **0 件と「まだ見ていない」と「届かなかった」を混同しない。**
  コーパスに届かなければ検索は 503 になり、記録も残らない。
- **照合できなかった主張は消えないが、支持の根拠にもならない。**
- **この製品は法的助言をしない。** 出力はすべて下書きで、判断は人間が行う。
  他人のために業として出願書類を作るのは弁理士の独占業務である（弁理士法72条）。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 検索が 503 になる | サイドカーが落ちている。`make corpus/serve` |
| 典拠が「未照合」のまま | 同上。復旧後にクレームチャートの「再照合する」 |
| 「この corpus.db はトークン化 v… で作られており」と出る | 全文検索の実装が変わった。`node src/cli.ts rebuild-index --db <file>` |
| 検索語が思ったように効かない | 検索式の欄の「分割した語」「落とした語」を見る |
| 公報が見つからない | `コーパス` の画面で取り込み範囲を確認する。範囲外なら「無い」ではない |
