# 典拠（Tenkyo）クレームチャート画面 — 方向性モック 3 案

弁理士・自己出願する発明者向けデスクトップ Web アプリ「典拠」の、同じ 1 画面（要件 B のクレームチャート）を 3 つの視覚言語で組んだ静的 HTML。人間が方向を選ぶための比較用で、実装コードではない。

| ファイル | 一言 |
|---|---|
| `direction-a.html` | **公報の組版** — 特許公報の活字組。隅付き括弧【 】を欄見出しに、罫だけで区切る |
| `direction-b.html` | **製図の引出線** — 特許図面の符号と引出線。所見の文から典拠札へ線を引き、引けない文は線が途切れる |
| `direction-c.html` | **検証台帳** — 出願台帳と検印。行頭に済・未・却の検印。棄却行は表から降ろして「棄却欄」で原文と対比 |

いずれも 1 ファイル完結（CSS インライン、外部依存は Google Fonts の `<link>` のみ、JS なし）。1440px 幅で確認済み。ページ本体の横スクロールは出ない（`scrollWidth = 1440`）。

## 画面が表現する唯一の主張

> AI の主張は (公報番号, 段落番号) に紐づき、その段落の原文に引用文が実在することを機械が照合できたときにだけ、支持された主張として表示される。照合できなかった主張は削除されず「照合できなかった」という事実とともに残り、支持の根拠には決してならない。

3 案とも次の 4 点でこれを可視化する。

1. 中央表の「照合状態」列（照合済み・未照合・棄却）。
2. 棄却行を**支持の根拠として読めない見え方**にする（案ごとに解き方が違う）。
3. 右の**典拠の余白**：所見の各文の右に典拠札（公報番号＋【段落番号】）が並び、札を持たない文だけが琥珀の下線と「典拠なし」を受ける。「不存在の主張は典拠を持てない」という文をあえて 1 つ入れ、思想が正しく働くことを示している。
4. 左索引の要件 D「典拠 0 件」を新規性の勝ち筋として際立たせる。

## 各方向の説明

### A. 公報の組版（`direction-a.html`）

- **題材**: 日本の公開特許公報の紙面。【 】を段落番号だけでなく画面構造の見出し装置に転用。カードは使わず、罫で囲んだ「欄」。角丸 0。
- **パレット**: 紙 `#FBFBF9` / 墨 `#14161A` / 補助墨 `#585C63` / 罫 `#D5D6D0` / 濃い罫 `#8A8D85` / 典拠の藍 `#1B4F8A` / 未照合の琥珀 `#8A6A12` / 棄却の朱 `#A32F26` / 天板 `#151A21`
- **書体**: display = Shippori Mincho、body = Noto Sans JP、data = IBM Plex Mono（公報番号・日付・件数・検索式のみ）
- **棄却の解き方**: 引用文に朱の打ち消し線、行全体を補助墨に沈め、朱の左罫で注記を添える。
- **勝ち筋 D**: 墨の太い左罫＋白地＋【新規性の勝ち筋】の明朝。色でなく組版で立てる。

### B. 製図の引出線（`direction-b.html`）

- **題材**: 特許明細書の「図面」。図面では符号（12, 14…）と引出線が本文と部品を一意に結ぶ。所見の一文一文に丸符号 ①〜⑤ を振り、水平の引出線で典拠札に結ぶ。結べない文は琥珀の破線が途中で終わり、開いた丸だけが残る。
- **パレット**: 図紙台 `#E6E9EB` / 図紙 `#FFFFFF` / 製図インク `#1F2328` / 薄墨 `#5F6870` / 細線 `#C9CFD3` / 検図の緑 `#1E6B52` / 仮線の琥珀 `#A06E00` / 赤鉛筆 `#B5301E`
- **書体**: Zen Kaku Gothic New 一家族（display 700 / body 400・500）、data = DM Mono
- **画面の骨格**: 上部は製図の表題欄（title block）。各欄に「図1」「図3」「図3a」の図番。
- **棄却の解き方**: 行全体に赤鉛筆の斜線ハッチング（製図の削除指示）を被せ、引用文と「関係」を打ち消す。
- **勝ち筋 D**: 二重丸の符号＋「先行技術に符号なし」＋斜線地。

### C. 検証台帳（`direction-c.html`）

- **題材**: 特許事務所の出願台帳と検印。1 行 = 1 典拠。行頭に必ず検印（済・未・却）が押され、支持の根拠は「済」の行だけ。棄却行は台帳から降ろし、別の**棄却欄**で「AI が引用したとする文」と「実際の【0032】」を左右に対比して残す。
- **パレット**: 台帳台 `#E8EAED` / 台帳紙 `#FFFFFF` / 鉄 `#16181C` / 鼠 `#6A7076` / 薄罫 `#D0D4D9` / 濃罫 `#7C838B` / 鴨の羽 `#0F5F6E` / 山吹の琥珀 `#946200` / 印朱 `#B02A22` / 帯 `#22262B`
- **書体**: BIZ UDPGothic 一家族（公文書向け UD 書体）、data = JetBrains Mono
- **密度**: 本文 12.5px・行間 1.7。6 典拠＋所見 5 文＋棄却欄＋検索式が 1440×900 に収まる（他 2 案は縦スクロールが出る）。
- **勝ち筋 D**: 索引で唯一の黒地反転。検印列にも何も押されない。

## 自己批評（「同種のどんな依頼にも出てくる generic 案ではないか？」）

| 方向 | 自問への答え | 判断 |
|---|---|---|
| A | 「紙色＋明朝見出し＋藍」は和風ドキュメント系で頻出する組み合わせで、その意味で最も既視感がある。ただし【 】を UI の見出し装置にすること、カードを一切使わず罫だけで欄を切ること、公報の「段落番号」を主役の列にすることは特許公報という題材からしか出てこない。指定パレットの範囲で最も“公報らしさ”に寄せた。 | 残す（指定案）。ただし色替えでなく組版で差を出せているかを見てほしい |
| B | 引出線と符号は「線でつなぐ UI」として存在するが、**線が途切れることで「典拠なし」を表す**のはこの製品の主張そのもの。表題欄・図番・削除ハッチングも図面からの引用で、SaaS の定石ではない。当初は引出線が飾りになりかけたため、破線＋開いた丸で「届かない」意味を持たせ直した。 | 残す |
| C | 高密度の管理テーブルは業務 SaaS の generic に最も近い。差は「検」列（検印）と、棄却行を表から降ろして原文と**並置**する棄却欄にある。これが無ければ作り直し対象だった。索引 D の黒地反転はやや強いので、採用時は太罫のみに弱める余地あり。 | 残す（棄却欄が主張を最も文字通りに実装している） |

3 案とも、Inter/Roboto 系、紫青グラデ、pill、色ストリップ、ALL-CAPS eyebrow、01/02/03 ナンバリング（B の丸番号は所見の文番号＝引出線の符号で、手順ではない）は使っていない。

## 推し

**C（検証台帳）を推す。次点は B。**

理由:

1. **主張の最も忠実な実装**が C の棄却欄。「削除せず、照合できなかった事実とともに残す」を、AI の主張文と実際の原文の左右対比で示すので、利用者は照合失敗の内容を自分の目で確かめられる。A・B の打ち消し／ハッチングは「支持に使えない」は伝わるが「何と食い違ったか」は注記文に頼る。
2. **実務者の作業机に合う密度**。弁理士は 1 要件あたり数件〜十数件の典拠を横並びで見比べる。1 画面に収まるのは C だけ。
3. **検印**という語彙が、照合状態を「AI が言った／機械が確かめた」の区別として日本の実務者に直感的に読める。

C を採る場合の持ち込み候補: B の「途切れる引出線」を典拠の余白に取り込むと、記憶に残る 1 点がより強くなる（C の空印だけでは弱い）。

## 要確認

## 決定（2026-09-04）

**C（検証台帳）を採用。** 人間が `design-select` のブラウザ提示で選択した。

実装は `services/patent_research`、トークンは `packages/ui/src/theme.css` の `tk-` 名前空間。
モックの生値（hex・px）は直接使わず、セマンティックトークンへ翻訳してある
（台帳台の上で AA に届かなかった鼠と琥珀は、色相を保ったまま明度だけ下げた）。

### 却下した方向（**この見た目へ戻さない**）

- **A. 公報の組版** — 明朝見出し＋藍＋罫だけの紙面。棄却行は打ち消し線で沈むが、
  **何と食い違ったのか**が注記文でしか分からない。製品の主張の核が弱い。
- **B. 製図の引出線** — 引出線が途切れることで「典拠なし」を表すのは強かったが、
  1 画面に収まらず、実務者が典拠を横並びで見比べる密度に足りない。
  ただし「**届かない線**」という発想は、典拠の余白の実装で参考にする価値がある。

### C を採るときの持ち込み（Fable の助言）

- 索引の要件 D「典拠 0 件」の黒地反転は強すぎるので、太罫のみに弱める。
- B の「途切れる引出線」を典拠の余白に取り込むと、記憶に残る 1 点が強くなる。
