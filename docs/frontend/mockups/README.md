# デザインモック台帳

`/design-select` で人間が選んだ HTML モックを `docs/frontend/mockups/<name>/` に置き、ここに 1 行で記録する。目的は 2 つ:

1. **選ばれた方向**を後から参照できるようにする（新しい画面は既存モックの語彙で作る）。
2. **却下された方向**を明文化して、同じ見た目に戻らないようにする。

## 採用

| モック | 画面 | 決定日 | メモ（シグネチャ要素・トークンの要点） |
|---|---|---|---|
| [`eyex/`](./eyex/index.html) | EYEX予約 全68画面（起動・認証・トップ・予約5工程・台帳・来店受付・顧客台帳・分析・設定・お客様向けWeb予約・例外） | 2026-08-28 | iPad 11インチ横向き 1194×834 / Web予約のみ iPhone 390×844。左サイドバー（216px、たたむと76px のアイコンだけの柱）が行き先を持つ。台帳は縦=担当・設備、横=時間で、30分ごとの薄い線と1時間ごとの線を**背景**に通す（帯をまたいでも途切れない）。来店回数の丸い印、予約のドラッグ移動と重なり警告、受付中の録音表示。書体は iPadOS 既定（HIG）、緑は `#17705a` ひとつ。 |

## 却下（この方向には戻さない）

| 却下した案 | 画面 | 理由 |
|---|---|---|
| `eyex-reservation/`（2026-08-26 採用 → 2026-08-28 破棄） | 全画面 | 情報を詰め込みすぎていた。1画面に主役が複数あり、白い箱と説明文が多く、余白が無い。行き先が上のバーに散っていて、台帳に時間のグリッドが無く、予約の置き場所を目で追えなかった。**モックも実装も削除済み。** |
| 一般的な管理ダッシュボード型 | トップ | 最初に予約を取る操作が埋もれ、電話対応開始までの判断が増える。 |
| 担当者・設備を同列に並べただけのタイムライン | 予約台帳 | 眼鏡店の接客工程を表現できず、同一予約が重複して見える。 |
| 顧客起点だけの予約フォーム | 予約入力 | 電話で最初に聞く日・時間・来店目的の自然な順序と合わない。 |
| 台帳に「空き」の大きな札を並べる | 予約入力 3/5 | 希望の日時はもう決まっているので、空きを大きく出す意味が無い。薄い線だけで置き場所を示す。 |
| TORETAの配色・形状の完全模倣 | 全画面 | 取り込むのは操作原則と情報構造に限定し、EYEX予約独自の視覚言語を維持する。 |

## 使い方

- モックの生値（hex・px）を React にコピペしない。**`packages/ui/src/theme.css` のセマンティックトークンへ翻訳**してから実装する（`../DESIGN_RULE.md` ルール 5）。
- モックは 1 状態しか描いていない。ローディング / 空 / エラー / レスポンシブ（375px〜）は DESIGN_RULE の品質フロアで補完する。
- `/design-select` をやり直すのは**見た目の方向そのものを変えたいとき**だけ。
