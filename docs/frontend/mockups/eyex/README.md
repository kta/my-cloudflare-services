# EYEX予約　画面モック（0ベース版）

眼鏡店チェーン **EYEX** 向けの予約管理・顧客管理・Web予約システムの画面モック。
発注元に見せるための静止画のモックであり、実装ではない。

- 一覧: [`index.html`](./index.html)（画像つきの目次。ブラウザで開く）
- 画面: `screens/<画面ID>.html` — 1画面1ファイル
- 画像: `images/<画面ID>.png` — 上の HTML を撮ったもの
- 設計システム: [`assets/eyex.css`](./assets/eyex.css) — 色・寸法・部品はここだけが持つ

## 使い方

```sh
cd docs/frontend/mockups/eyex

node shoot.mjs              # 全画面（68枚）を撮り直す
node shoot.mjs HOME LEDGER  # 名前に HOME か LEDGER を含む画面だけ
node index.mjs              # index.html を作り直す
```

`shoot.mjs` は Chromium（リポジトリの Playwright）で `screens/*.html` を開き、
`id="screen"` の要素だけを切り取る。画面の外に書いた説明文は写らない。
中身が枠からはみ出していると「※はみ出し」として報告する。

## 何を真似て、何を変えたか

画面の**操作の順序と情報の並べ方**はトレタ（予約台帳）から取り込んでいる。

- トップは「主操作2つ（新しい予約を取る／予約を変更する）＋日常の参照リスト＋日付の帯」。
  電話が鳴ってから予約を取り始めるまでの判断を減らす形。
- 予約は**会話の順**に1工程1問。日時 → ご来店の目的 → 担当と場所 → お客様 → ご確認。
- 台帳は**縦が人・場所、横が時間**。現在時刻の線、ウォークインの行、出どころの色分け。
- 顧客台帳は「条件で絞る／一覧／詳細」の3面。分析はタブで指標を切り替える。
- 設定は左に分類、右にグループ表（iOS の設定と同じ読み方）。

一方で、次はすべて EYEX 向けに作り直している。

- **配色・書体・角の形**はトレタを写していない。ヘッダーの緑は白文字とのコントラストが
  WCAG AA を満たす濃さ（`#17705a`）にした。書体は iPadOS の既定（SF / ヒラギノ）。
- **扱う商材が違う**。人数・テーブル・コースの代わりに、**ご来店の目的・所要時間・担当者の技能・
  検査機と相談カウンター・度数と現在のメガネ**を情報の中心に据えた。
- **端末の使い分け**（個人の端末／レジ横の共有端末）と**PIN**、共有端末での自動マスクを足した。
- **受付中の録音**を全工程で見せる（予約フローは下の帯、確認画面は右下の常駐表示）。
- **手書き**（Apple Pencil）でご要望を残す面を足した。

## 画面をつくるときの決め（余白を守るための引き算）

発注元の指摘「シンプルさが足りない。余白の美しさを忘れないで」を受けて、全画面をこの規準で
作り直している。**空いた場所を埋めるために要素を足さない。下や右が空いているのは正しい状態。**

| 規準 | 上限 |
|---|---|
| 主役 | 1画面に1つ |
| 白い箱（枠線つきのカード） | 3枚まで。並べたいだけの情報は罫線（`.lines`）か余白で区切る |
| 説明文（補足の段落） | 2つまで・各1行 |
| 一覧・表の行 / 選択の札 | 8つまで |
| 状態の札（`.tag`） | 3つまで |
| グラフ | 1つ |
| 文字の段 | 見出し22px／本文16px／補足13px の3段まで |
| 余白 | 画面の外周 32〜44px、かたまりの間 24〜32px |

## 画面の骨格（2026-08-28 の指摘を反映）

- **左サイドバー**が行き先を持つ（予約台帳／来店受付／予約を検索／受付履歴／顧客台帳／分析／設定）。
  上のバーには店名・日付・お知らせだけを残した。
  **つまみで細い柱（76px・アイコンだけ）にたためる。** 横に広い画面（台帳・分析・設定・来店受付・
  顧客一覧）はたたんだ状態を既定にしてある。予約フローと業務開始の画面にはサイドバーを出さない。
- **台帳の時間グリッド**は、セルの枠線ではなく背景（`.tt-bg`）として通す。30分ごとの薄い線と
  1時間ごとの少し濃い線が、予約の帯をまたいでも途切れないので、空いている枠を置き場所として読める。
  現在時刻は台帳の中では線だけを引き、文字はツールバーの `.nowchip` に置く。
- **来店回数**（`.visits`）をお名前の右に出す。3回目以上は薄い緑、はじめてのお客様は薄い橙。
  30分幅の狭い帯と、回数の列がすでにある画面には入れない。
- **予約の入力**（3/5 担当と場所）は、希望時刻がすでに決まっている前提で作る。
  「空き」の大きな表示は置かず、置いたご予約は指でつかんで動かせる（`.grip` / `.ghost`）。
  先約と重なると `.appt.under` の上に `.appt.clash` を重ねて警告し、同じ時刻で受けられる担当・設備を
  `.appt.pick` と右の候補で示す。担当が決まっていないときも同じ形で候補を出す。
- 録音の許可を説明するだけの画面は置かない（受付中の録音は、予約フローの下の帯で常に見せる）。

> 2026-08-28 追記: `assets/eyex.css` と `screens/HOME.html` が一度古い版に巻き戻り、
> サイドバー・来店回数・時間グリッド・ドラッグの定義が失われていた。上の骨格に合わせて
> 書き直し、全画像を撮り直している。サイドバーのアイコン（`data-icon`）だけは元の線画が
> 残っていないため引き直した。形はわずかに違うが、意味と置き場所は変えていない。

## 色

`assets/eyex.css` の `:root` が唯一の出どころ。画面側で新しい hex を書かない。

| 役割 | 変数 | 値 |
|---|---|---|
| ブランド・主操作・ヘッダー | `--brand` | `#17705a` |
| 選択の塗り | `--brand-tint` | `#e4f0eb` |
| Web予約 | `--web` | `#1c5c8c` |
| ウォークイン | `--walkin` | `#9a5a15` |
| 取消・警告・危険 | `--alert` | `#97302b` |
| 埋まっている枠 | `--busy` | `#cdd5d1` |
| 下地／面／罫線 | `--canvas` / `--surface` / `--line` | `#f1f4f2` / `#ffffff` / `#d3dbd7` |

## モックが描いていないこと

1状態しか描いていない画面がある。読み込み中、ふりがなの自動入力、文字を大きくしたとき、
Split View、VoiceOver の読み上げ順は、この画像の外で決める必要がある。
実装するときは、ここの hex や px を貼らずに `packages/ui/src/theme.css` の
セマンティックトークンへ翻訳する。

## 分析のモック無し3タブ（2026-08-31 design-select）

- **採用: 案B** — 「予約の入口」「来店回数」は短い4分類なので縦棒を使い、長い業務語を持つ
  「ご来店の目的」だけ既存の担当者タブと同じ横棒へ切り替える。正式モックは
  [`ANALYTICS-SOURCE`](./screens/ANALYTICS-SOURCE.html)／
  [`ANALYTICS-VISITS`](./screens/ANALYTICS-VISITS.html)／
  [`ANALYTICS-PURPOSE`](./screens/ANALYTICS-PURPOSE.html)。
- **不採用: 案A** — 3タブをすべて縦棒に統一する案。目的名の折り返しでラベルと値の対応が弱まり、
  iPad Split View と文字拡大時に比較しにくくなるため戻さない。
- 3タブとも、グラフ1つ・「何をいつ基準にどの母数で数えたか」の定義1行・まとめ3項目に限定する。
- P9ではP10が所有するお知らせ件数や通知UIを追加しない。
