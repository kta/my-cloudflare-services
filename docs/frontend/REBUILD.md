# フロントエンドの作り直し — 承認済みモックへ寸分違わず合わせる

`docs/frontend/mockups/eyex-reservation/` の承認済みモックを正として、フロントエンドの
見た目を 0 から作り直す。バックエンドとの接続は当面持たない。

## 進め方

1. **設計** — モックの CSS を実測して、共通の語彙（`src/web/design/`）へ翻訳する。
2. **実装** — 1 画面 1 ファイルで `src/web/gallery/screens/<画面ID>.screen.tsx` を書く。
   固定値だけで描き、通信も権限判定も持たない。
3. **突き合わせ** — Playwright でモックと 1 枚ずつ重ね、違う画素を数える。
4. **差分が消えるまで 1 に戻る。**

## 道具

| コマンド | 何をするか |
|---|---|
| `node e2e/mock-reference.capture.ts` | モックから基準画像 `docs/frontend/reference/ref--<ID>.png` を作る |
| `node e2e/gallery.diff.ts [ID...]` | 突き合わせ台を撮って基準と重ね、不一致の割合を出す |
| `node e2e/crop.mjs <png> <out> <x> <y> <w> <h> [倍率]` | 差分画像の一部を拡大して切り出す |
| `node e2e/bands.mjs <ID>` | 不一致が多い横帯を上位から出す（どこを見るかの当たりを付ける） |

事前に 2 つのサーバーを上げておく。

```sh
# リポジトリの root をそのまま配る（モックと webfont を読むため）
python3 -m http.server 4176
# 突き合わせ台
pnpm --filter @app/glasses_management exec vite --port 5199 --strictPort
```

`GALLERY_BASE` を渡せば別ポートの dev サーバーを見に行く（並行作業のとき）。

出力は `docs/frontend/diff/impl--<ID>.png`（実装）と `diff--<ID>.png`（違う画素を赤で塗る）。

## 基準画像について

基準は承認済みモックの見た目そのものである。余白も文字寸法もモックのまま撮り、
アプリ側がそれに合わせる（`src/web/app.css` がブラウザ既定の余白・見出し寸法を
明示的に持ち直している）。

ただし次の 2 点だけは「モックの書き漏れ」として正規化してから撮る。理由も含めて
`e2e/mock-reference.capture.ts` に書いてある。

- **ボタンの `font:inherit` / `color:inherit` の抜け**。同じ画面の中でもボタンごとに
  有無がばらついており、抜けているボタンだけシステム書体・黒文字・13px に落ちる。
  設計ではなく書き漏れなので、宣言どおり本文の書体と文字色を継がせる。
- **台紙と端末の外枠**。モックは端末の絵を見出し付きの台紙に載せている。台紙の余白で
  端末が小数の位置に置かれ、字が半画素ずれる。対象の 1 面だけを原点へ寄せ、
  ビューポートをその実寸にしてから撮る。

## 合格の目安

**基準画像と実装の撮影が、バイト単位で一致すること。** 2026-08-28 時点で 44 画面
すべてが一致している。ここまで来ると割合も差分画像も見る必要がない。

崩れたときは `node e2e/overlay.ts [ID...]` を使う。1 枚の画像に 5 面（基準・実装・
重ね合わせ・差分・ずらし探索の結果）を並べ、次を数字で出す。

- **ずれ** — 上下左右に ±8 画素ずらして最も合う位置を探す。`0,0` 以外なら面ごと
  ずれている。字の輪郭の揺れと配置のずれを取り違えずに済む。
- **平坦な色の取り違え** — 対の両方が「その画像で広い面積を占める色」であるときだけ
  拾う。`#fff0ed` と `#fff1ed` のような塗りの取り違えが、割合に出なくてもここに出る。

重ね合わせの面は、基準を赤・実装を青の版にして 1 枚に刷ったもの。合っていれば灰色に、
ずれていれば赤と青が分かれて見えるので、ずれの向きが目で読める。

`node e2e/gallery.diff.ts` は割合と差分画像だけを出す軽い方。日常はこちらでよい。

## 一致させるまでに詰まったところ

同じ轍を踏まないように残す。

1. **書体が別物だった。** `packages/ui` が Fraunces と Public Sans を読み込んでいた。
   モックは IBM Plex Sans JP。これに気づくまで、何を直しても全画面がうっすら違った。
2. **モックが書体を宣言だけして読み込んでいない。** ボタンによって `font:inherit` /
   `color:inherit` の有無がばらついており、抜けているボタンだけシステム書体・黒・
   13px に落ちる。書き漏れとして正規化してから撮る。
3. **台紙で端末が小数の位置に置かれる。** 字が半画素ずれるので、対象の 1 面だけを
   原点へ寄せ、ビューポートをその実寸にしてから撮る。
4. **基準側のサブセットを絞ると記号だけ字形が変わる。** 日本語と欧文だけ読ませていた
   ときは、`●` や `✓` が基準の側でシステム書体へ落ちていた。アプリと同じ一式
   （`400.css` など全サブセット）を読ませる。**これで 43 画面が一気に一致した。**
5. **半透明の枠を不透明な近似色に置き換えない。** `#ffffff70` は 43.92% で、
   Tailwind の 1% 刻みでは表せない。緑に重ねた結果の色に置き換えると直線は合うが、
   角の丸みで下地との混ざり方が変わる。半透明のままトークンに持つ。

## 規約

- 色・角丸・文字寸法は `packages/ui/src/theme.css` のセマンティックトークンだけを使う。
  Tailwind 既定パレット（`bg-blue-500`）と任意値（`p-[13px]` / `text-[#hex]`）は禁止。
  モックに無い段が必要になったら、まずモックを見直す。それでも要るならトークンを足す。
- 4 の倍数でない実測値（列幅 390px / 250px、`1.4fr 1fr 1fr auto` など）は、
  純粋な配置としてインライン `style` で持つ。
- 日本語を `font-mono` で描かない。IBM Plex Mono は和文グリフを持たない。
  等幅は時刻・ID・数値だけ。
- コメントは日本語で、「何を」ではなく「なぜ」を書く。
