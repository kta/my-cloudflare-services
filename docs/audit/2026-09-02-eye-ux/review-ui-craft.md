# UI クラフトレビュー — 視覚と構成の質

対象は「押せるか」ではなく「見て分かるか」である。実機（ポート 4331・1194×834・JST 2026-08-27 11:08 固定）で 9 画面を撮り、承認済みモック 68 枚と並べて見た。既存 134 件と重複する所見は載せていない。

## 総評

トレタとの差は機能数ではなく、**帯の中の文字の序列**に出ている。台帳の予約帯は 5 行すべてが 13px で、いちばん太いのは `11:00–12:00` という時刻、お客様のお名前は 3 番目に弱い（実測 700/600/400 の 3 段だけ、寸法差ゼロ）。モックは時刻を帯の中に書かず、お名前を 17px 相当の最強要素に置いている。x 軸が既に時刻を表している盤で時刻をいちばん強く刷るのは、盤としての読みを捨てているに等しい。ここが「ぬるぬるしない」より先に効く差である。

次に効くのが**シェルの不安定さ**である。左ナビは操作していないのに画面ごとに 216px と 76px を行き来し（トップ 216 → 来店受付 76 → 受付履歴 216 → 顧客台帳 76）、本文が 140px 横に飛ぶ。お知らせのベルは 3 画面で黙って消える。アニメーションの不足が問題として挙がっているが、その前にそもそも**動いてはいけないものが動いている**。

余白は設計されていない。`packages/ui/src/theme.css` に spacing トークンが 1 つも無く、業務 SPA は `gap` を 20 段・`py` を 21 段（`py-0.75`=3px / `py-1.25`=5px / `py-3.75`=15px を含む）使っている。段が無いので近接の原則が働かず、設定画面では見出しが前のカードの底辺に 0px で重なっている。

もうひとつ通底しているのが**既定値を置かない癖**である。予約を取る は本日を選ばずに開き、顧客台帳・予約を探す・受付履歴 は 1 件も選ばずに開く。承認済みモックには右ペインが空の絵が 1 枚も無い。画面の 30〜58% が灰色の 1 行だけで埋まっているのは、余白の設計ではなく初期選択の不在である。

寸法・色・言葉づかいの土台は良い。壊れているのは**序列・段・既定値**の 3 つで、いずれも部品側と初期 state で直せる。

## 所見

### UI-01 台帳の予約帯で、お客様のお名前がいちばん弱い
- **重大度**: S1
- **画面**: 予約台帳（タイムテーブル表示）
- **いま起きること**: 11:00 田中様の帯（x=386, y=158, 128×109px）の中身は 5 行あり、上から `11:00–12:00`（13px / 700 / 等幅）、`田中 花子 様`（13px / 600）、`4回目`（11px / 600 / 等幅）、`新調相談・視力測定`（13px / 400・2 行に折り返し）。**寸法の差は 0**、太さの 3 段だけで序列を作っている。結果として目に最初に入るのは等幅太字の時刻で、名前はその下に沈む。時刻は帯の x 位置が既に表しているので、この情報は 2 度描かれている。
- **モックとの差**: `LEDGER-STAFF.png` の同じ帯には時刻テキストが無い。先頭が `田中 花子 様`（実測 2388px 幅で 40px ≒ 1194px 換算 20px・太字）、次に `4回目` の丸札、最後に用件。**モックが正しい。**
- **あるべき姿**: 帯の第 1 行はお客様のお名前（`--text-lead` 17px / 600）。時刻は 30 分帯など名前が入らない高さのときだけ出す。用件は `--text-note`。
- **根拠**: 実測（`scratchpad/m2.mjs` の出力）／ `shots/B-予約台帳.png` ／ `docs/frontend/mockups/eye/images/LEDGER-STAFF.png`
- **直し方の案**: 帯の中身を「名前 → 札 → 用件」の 1 部品に切り出し、高さで表示要素を落とす（LEDGER-05 の「30 分幅で名前が出ない」も同じ部品で解ける）。
- **見積り**: S

### UI-02 余白に段が無く、20 通りの gap が併存している
- **重大度**: S2
- **画面**: 全画面
- **いま起きること**: `packages/ui/src/theme.css`（111 行）は書体・寸法・色・角丸を持つが、**spacing トークンが 0 個**。業務 SPA の実使用は `gap` 20 段（`gap-0.5` 〜 `gap-14`）、`mt` 21 段、`py` 21 段、`px` 19 段で、`py-0.75`（3px）・`py-1.25`（5px）・`py-3.75`（15px）といった 4px 未満の刻みまである。段が無いので「関係が近いから詰める」という判断が効かず、設定画面では 32px（`お店の基本` → カード）と 0px（`行き方のご案内` → 前のカード）が同じ意味の位置に並ぶ（UI-07）。
- **あるべき姿**: `theme.css` に 4 / 8 / 12 / 16 / 24 / 32 / 48 の 7 段を置き、その名前だけを使う。`--text-*` と同じ思想（「ここに無い大きさはモックに無い」）を余白にも適用する。
- **根拠**: `packages/ui/src/theme.css:20-111`（`@theme` に spacing 無し）／ `services/glasses_management/src/web` の grep 集計
- **直し方の案**: トークン追加 → Biome または独自 lint で素の `gap-2.5` 等を禁止 → 画面ごとに置換。DESIGN_RULE は任意値（`p-[13px]`）を禁じているが、`py-3.75` は任意値ではないので現在すり抜けている。ここを塞ぐ。
- **見積り**: S（トークン）＋ M（適用）

### UI-03 「選択中」と「主操作」が同じ緑・同じ形で、ナビに緑の塊が 2 つ並ぶ

### UI-04 左ナビの幅が、操作していないのに画面ごとに 216px と 76px を行き来する
- **重大度**: S1
- **画面**: シェル全画面
- **いま起きること**: `たたむ` を一度も押さずにナビを歩くと、幅が トップ 216 → 来店受付 76 → 受付履歴 216 → 顧客台帳 76 → 分析 76 → 設定 76 → 予約台帳 76 → 来店受付 76 → トップ 216 と変わる。畳まれた側ではラベルが全部消え、時計・虫めがね・横線・人・折れ線・つまみの 6 アイコンだけが残る。本文の左端が 140px 単位で瞬間移動し、モーションも無い。「受付履歴は広く、顧客台帳は狭い」という規則は業務上の意味を持たない。
- **モックとの差**: モックは画面ごとに畳んだ／広げたの両方を描いており（`HOME.png` は広い、`LEDGER-STAFF.png` は畳んだ）、実装はそれを「画面の属性」として実装したように見える（推定）。モックは 1 枚 1 枚が独立した絵なので、遷移の連続性を表していない。**実装の解釈が誤りである。**
- **あるべき姿**: 畳む／広げるは利用者の選択であり、選んだ状態は画面をまたいで保つ。画面側から変えない。どうしても台帳だけ広く使いたいなら、遷移時に「ナビを畳みました」と分かる 0.2s のアニメーションを付けるか、台帳側に全画面ボタンを置く。
- **根拠**: 実測（`scratchpad/m3.mjs` の nav 幅ログ）／ `shots/A-home.png`（216px）と `shots/B-来店受付.png`（76px）
- **直し方の案**: 畳み状態を 1 つの永続 state に統一し、画面から書き換えている箇所を外す。
- **見積り**: S

### UI-11 設定の「保存」は押せないことが伝わらず、「変更を捨てる」はボタンに見えない

- **いま起きること**: 画面上端の 2 つの操作は両方 `disabled` だが、見た目が正反対に外れている。`保存` は 背景 `#e9eeeb`・文字 `#626e69`・1px の枠つき（66×44px）で、**この製品の押せる副ボタン（絞り込み・本日 など）とほぼ同じ姿**である。`変更を捨てる` は 背景透明・枠なし・灰色文字（128×44px）で、**ただの説明文にしか見えない**。結果、押せないものが押せそうに、押せるものが押せなさそうに見えている。
- **モックとの差**: `SETTINGS-STORE.png` の `保存` は緑の塗りの主ボタン、その左に `未保存の変更 2件` の札、さらに左に緑文字の `キャンセル`。変更のあるパネルには `未保存` バッジが付く。**モックが正しい。**実装には未保存件数の表示が無く、SET-10（保存の単位が分からない）の見た目側の原因になっている。
- **あるべき姿**: 主操作の `保存` は変更が無いときも緑の塗りのまま不透明度と `aria-disabled` で落とす（押せないことは色ではなく彩度で示す）。未保存件数の札を添える。`変更を捨てる` は枠のある副ボタンにする。HIG-03（押せる／押せないが見た目で区別できない）の設定画面版だが、こちらは**主操作が最も弱い要素になっている**点が別問題である。
- **根拠**: 実測（`scratchpad/m5.mjs`：`保存` bg `rgb(233,238,235)` border 1px、`変更を捨てる` bg transparent border 0px）／ `shots/B-設定.png`
- **直し方の案**: 無効状態を `opacity-40 + cursor-not-allowed` の 1 語彙に統一し、`focusRing` と同じく文字列でエクスポートする（原因B と同じ配り方）。
- **見積り**: S

### UI-12 取り消しの赤を「担当が未定」に使っている
- **重大度**: S3
- **画面**: 予約台帳（タイムテーブル）
- **いま起きること**: `担当が未定` の 3 件は `--color-danger-soft`（#fbe9e7）の地に `--color-danger`（#97302b）の左バーで描かれ、**取り消し・警告・破壊的操作と同じ赤**を使っている。`theme.css:83` は `--color-danger` を「取消・警告・現在時刻の線・破壊的操作」と定義しており、定義に反している。盤を見た店員は赤い帯を「取り消された予約」と読む。
- **モックとの差**: `LEDGER-STAFF.png` も同じ赤を使っている。**モックが間違っている。**担当未定は失敗ではなく「これから決めること」なので、`--color-amber`（失敗ではない注意）が定義どおりである。
- **あるべき姿**: 担当未定は amber、取り消しは danger。色だけに頼らず文字を添える方針（`theme.css:78`）は既に守られているので、色を替えるだけでよい。
- **根拠**: `packages/ui/src/theme.css:83`（danger の定義）と `:86`（amber の定義）／ `shots/B-予約台帳.png`
- **直し方の案**: 台帳の帯の色分けを 1 つの関数に集約し、danger は取消のみに限定する。
- **見積り**: S

### UI-13 分析だけがネイティブの `<select>` を使っている
- **重大度**: S3
- **画面**: 分析（全タブ）
- **いま起きること**: 期間（`2026年8月`）と店舗（`店舗：銀座店`）が素の `<select>` 2 つで、OS 既定の枠・矢印・角丸で描かれる。製品の他のすべての選択肢は角丸 8px の自作の札／ピルである。iPad では押すと OS のホイールが立ち上がり、この画面だけ別のアプリの操作感になる。
- **モックとの差**: `ANALYTICS-TOP.png` は白い角丸ピル＋自前の `▾` で描いている。**モックが正しい。**
- **あるべき姿**: 他画面と同じ札／ポップオーバーにそろえる。
- **根拠**: 実測（`scratchpad/m5.mjs`：`select` 2 個、幅 149 / 162px）／ `shots/B-分析.png`
- **直し方の案**: `packages/ui` に `Select` を 1 つ作り、分析の 2 か所を置換する。
- **見積り**: S

## 良い点（壊してはいけないもの）

- **色トークンの設計そのもの。** `theme.css` は 111 行で、色ごとに「なぜこの値なのか」（モック実測値が 1.84:1 で届かないので明度だけ下げた 等）と、どこで使うかがコメントに書いてある。`--color-grid-line` が `--text-grid` と衝突する Tailwind v4 の罠まで明記してある。この文書性は珍しく、消してはいけない。
- **1 書体・ウェイトだけで段を作る方針。** 見出し用の別書体を持たない判断は正しく、業務画面の落ち着きを作っている。UI-01 で足りないのは書体ではなく寸法の段である。
- **和文の禁則と字送り。** 「お日にちはいつがよろしいですか？」のような長い問いかけが 22px で 1 行に収まり、どの画面でも 1 行の文字数が伸びすぎていない。
- **予約を取る／顧客台帳の右ペインの情報設計。** 「ここまでのご予約」「お客様の行をお選びください」といった枠組み自体はモックどおりで、中身が埋まれば効く。捨てずに UI-06 / UI-10 で埋めるべきもの。
- **上バーの二段組（店名＋いまの画面名）。** 8 画面で崩れておらず、店舗を取り違える事故を防いでいる。
- **等幅を時刻・番号・数値だけに使う規律。** `10:00`／`EY-2608-0142`／`03-3571-0001` で守られており、桁が揃って読める。UI-01 で外すのは帯の中の時刻だけで、この規律自体は維持したい。
