# shell-home（起動導線・アプリシェル・トップ・お知らせ）— 実機監査所見

環境: `vite preview` :4300 / :4319（使い捨て D1 + seed）／Playwright Chromium 1194×834／
時刻を JST 2026-08-27 11:08 に固定。実装は `src/web/start/` `src/web/login/` `src/web/shell/`
`src/web/App.tsx` `src/web/home/` `src/web/mode/` `src/web/alerts/`。

## 監査した画面・経路
- 起動〜業務開始（お店のコード → 端末モード → 置き場所 → 共有PIN／スタッフ選択 → 個人PIN）
- PIN を 3 回間違えたときのロックアウト
- 共有トップ・個人トップ・店舗切替チップ・お知らせ 3 件の各アクション
- ナビの「たたむ」の保持、ブラウザの戻る、リロード、3 分放置のロックベール
- 8 画面のランドマーク構造と URL / `document.title`

## 総評 — **30 / 100**

起動導線の言葉づかい（「この iPad の使い方を決めてください」「選んだ置き場所の名前が、
そのまま記録に残ります」「個人を選ばずにできる／ご本人の確認が必要」）は非常に良い。
だが**アプリの土台に 3 つの構造的な穴**がある。

1. **URL が常に `/` で動かない** → ブラウザの戻るを押すと `about:blank` になり**アプリから出る**。
   リロードすると業務セッションが切れて**置き場所選択と PIN からやり直し**。
2. **存在しない店舗コードでアプリ本体に入れてしまう**（PIN も端末設定も飛ばす）。
3. **トップが空っぽ**。出勤したアルバイトが最初に見る画面に、今日の情報が 1 つも無い。
   個人端末で入っても、その人自身の本日の予約が 1 件も出ない（`MyReservations` は無言で空）。

## 所見一覧

### SHELL-01 ブラウザの戻るでアプリから出て真っ白になる
- **重大度**: **S1**
- **画面**: 全画面
- **再現**: 業務画面で予約台帳を開き、ブラウザの戻る（iPad なら二本指の右スワイプ）。
- **いま起きること**: URL が **`about:blank`** になり、**真っ白な画面**になる。
  画面遷移で `history` に積まれていないので、「戻る」の 1 回目でアプリ自体を出る。
  レジ横の iPad で誰かが誤って画面端をスワイプしただけで、業務が止まる。
- **根拠**: 実測（`page.goBack()` 後の `location.href === 'about:blank'`）
- **直し方の案**: 画面ごとに URL を持たせる（`/ledger`, `/customers/:id` …）。
  最低限、`history.pushState` で戻り先を作り、最初の画面で戻るを抑止する。
- **見積り**: M

### SHELL-02 リロードで業務セッションが切れ、置き場所選択と PIN からやり直しになる
- **重大度**: **S1**
- **画面**: 全画面
- **再現**: 顧客台帳を開いた状態でページを再読み込みする。
- **いま起きること**: トップにすら戻らず、**「この端末はどこに置きますか？」**まで巻き戻る。
  そのあと共有 PIN の入力もやり直し。
  予約の入力途中なら、伺った内容は失われる。
  iPad の Safari はメモリ不足でタブを自動的に再読み込みするので、**業務中に普通に起きる**。
- **根拠**: 実測（`page.goto('/')` 後の画面）、`shots/shell-home/05-after-reload.png`
- **直し方の案**: 端末セッションを `localStorage` に持たせ、再読み込みで復帰させる
  （PIN の再入力を求めるなら、置き場所選択は飛ばす）。
  入力途中の下書きも同様に残す。
- **見積り**: M

### SHELL-03 存在しない店舗コードでアプリ本体に入れてしまう
- **重大度**: **S1（セキュリティと信頼）**
- **画面**: 最初の「お店のコード」
- **再現**: `nonexistent` と入力して「業務を始める」。
- **いま起きること**: 端末モード選択も置き場所選択も **PIN も飛ばして**アプリシェルに入る。
  - ヘッダは「EYE」「**営業中 10:00–19:00**」と実在しない店の営業情報を表示
  - 左ナビはフル機能（予約を取る／予約台帳／設定 …）が押せる状態
  - 唯一の手がかりは本文下の灰色の小さな一文「お店がまだ登録されていません。」
  - 左下は「nonexistent の端末／共有で使っています」
- **あるべき姿**: コードが存在しなければ入口で止め、
  「お店のコードが見つかりません。レシートの控えか店長にご確認ください」と伝える。
- **根拠**: 実測、`shots/shell/02-orgcode-wrong.png`
- **見積り**: S

### SHELL-04 最初の「お店のコード」画面が未設計
- **重大度**: S2
- **画面**: 起動直後
- **いま起きること**: 承認済みモック 68 枚にこの画面は無い（モックは `START-DEVICE-MODE` から始まる）。
  1194×834 の iPad に、左寄せで幅 448px の入力欄とボタンが 2 つ縦に並ぶだけ。
  ロゴも説明もヘルプも無く、「お店のコードとは何か」「どこに書いてあるか」が読めない。
  プレースホルダの「例: eye」だけが手がかり。
- **根拠**: `shots/shell/01-orgcode.png`
- **見積り**: S

### SHELL-05 トップが空っぽで、今日の情報が 1 つも無い
- **重大度**: **S1**
- **画面**: トップ（共有・個人とも）
- **いま起きること**: カード 2 枚（新しい予約を取る／予約を変更する）と
  店舗切替チップ 2 つだけで、**iPad 画面の半分以上が空白**。
  本日 8/27 には予約が 12 件入っているのに、トップには件数すら出ない。
  出勤したアルバイトが知りたいこと——
  今日は何件か／次に来るのは誰か／いま何人待っているか／
  自分の担当は何件か／未対応のお知らせは何か——が**すべて欠けている**。
  お知らせは右上のバッジ「3」だけ。
- **あるべき姿**: トップを本日の状況板にする。
  トレタのホームは「今日の予約数・来店済み・キャンセル・未対応」を最初に出す。
- **根拠**: `shots/shell/20-home.png`、`shots/shell-home/02-personal-home.png`
- **見積り**: M

### SHELL-06 個人端末なのに自分の予約が出ない（`MyReservations` が無言で空）
- **重大度**: **S1**
- **画面**: 個人トップ
- **再現**: 個人端末モードで 佐藤 美咲 として業務を始める。
- **いま起きること**: 個人トップは**共有トップと 1 文字も違わない**
  （左下が「佐藤 美咲の iPad／個人で使っています」になるだけ）。
  佐藤 美咲 は本日 11:00 と 14:00 と 17:00 に予約を持っているのに、
  **自分の予約が 1 件も出ない**。
  `MyReservations` は `App.tsx:878` で描画されているが、
  実測で本文に何も出力していない（空状態のメッセージすら無い）。
- **根拠**: 実測（個人トップの全文）、`src/web/App.tsx:877-886`、`src/web/home/MyReservations.tsx`
- **直し方の案**: 個人モードでは「本日のあなたのご予約」を時刻順に出す。
  0 件なら「本日のご担当はありません」と言う（無言にしない）。
- **見積り**: M

### SHELL-07 店舗切替チップが `onClick` を持たない（完全な飾り）
- **重大度**: **S1**
- **画面**: トップ
- **再現**: 「EYE 丸の内店へ切り替える」を押す。
- **いま起きること**: **何も起きない**（実測で本文差分ゼロ）。
  コードにも `onClick` が無い:
  ```tsx
  // App.tsx:865-871
  <button type="button" className={`min-h-11 rounded-full border ... ${focusRing}`}>
    {s.name}へ切り替える
  </button>   {/* onClick が無い */}
  ```
  トップ画面の 5 つの操作のうち 2 つが飾りである。
- **根拠**: 実測、`src/web/App.tsx:865-871`
- **直し方の案**: 店舗切替を実装する（または実装まで出さない）。
  `findings/reception.md` RECEP-01 と同じ「ハンドルの無いボタン」問題。
- **見積り**: M

### SHELL-08 お知らせのアクションが機能していない／行き先が正しくない
- **重大度**: **S1**
- **画面**: お知らせとアラート
- **いま起きること**:

  | アラート | ボタン | 結果 |
  |---|---|---|
  | 録音の保存に3回失敗しました | もう一度送る | **❌ 何も起きない** |
  | Web予約が2件、確認待ちです | 台帳で確認する | 台帳の本日ビューへ行くだけ（**該当の 2 件が示されない**） |
  | 視力測定機 B の点検 8/30 10:00–12:00 | 影響する予約を見る | 台帳の**本日**へ行く（**8/30 でも該当予約でもない**） |
  | — | すべて既読にする | 画面は変わるが**バッジは「3」のまま** |

  対応が必要と言われた 3 件のうち、**1 件は押せず、2 件は間違った場所へ連れて行く**。
- **根拠**: 実測（4 ボタンの押下前後の差分）
- **直し方の案**: 行き先に日付と対象を持たせる（`navigate('ledger', { date, ids })`）。
  「もう一度送る」を録音の再送 API に繋ぐ。既読でバッジを減らす。
- **見積り**: M

### SHELL-09 PIN ロックアウトの表示が壊れている
- **重大度**: **S1**
- **画面**: 共有 PIN / 個人 PIN
- **再現**: PIN を 3 回間違える。
- **いま起きること**: 赤帯に「**30秒お待ちください**」と出るが、
  - **カウントダウンが無い**（いつ再開できるか分からない）
  - テンキーは押せる見た目のまま
  - **「確定」ボタンのラベルが消え、空の白いボタンになる**
  - 「6桁のうち0桁を入力済み」「あと4桁で『確定』を押せます」という矛盾した案内が残る
- **根拠**: 実測、`shots/shell/14-pin-lockout.png`
- **直し方の案**: 残り秒数を 1 秒ごとに出す（「あと 23 秒でもう一度お試しいただけます」）。
  テンキーを明示的に無効化し、「確定」のラベルを消さない。
- **見積り**: S

### SHELL-12 【良い点】起動導線の言葉と、ロックベール
- **重大度**: —
- **観測**:
  - 端末モードの比較が「記録される名前／お客様の情報／暗証番号」の**3 項目 × 2 列の表**で読める
  - PIN 画面が「**個人を選ばずにできる**：予約を受ける・台帳を見る・ご来店を受け付ける／
    **ご本人の確認が必要**：録音の保全・注意ごとの公開・設定の変更」と、
    なぜ PIN が要るのかを先に説明する
  - PIN を間違えたとき「店長に暗証番号の再設定を頼む」という次の一手がある
  - スタッフ選択で「担当　本日休み」が出て、休みの人を選ばせない
  - **3 分放置でロックベールが動き、お客様の情報が `●●●● 様` `090-●●●●-●●●●` に伏せられる**
    （「2分間さわらなかったので伏せました。さわると元に戻ります。」）

  この配慮の水準がトップ画面や台帳には届いていない。
