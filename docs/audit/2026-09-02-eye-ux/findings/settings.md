# settings（設定）— 実機監査所見

環境: `vite preview` :4314（使い捨て D1 + seed）／Playwright Chromium 1194×834／
時刻を JST 2026-08-27 11:08 に固定。実装は `src/web/settings/`。

## 監査した画面・経路
- 8 パネル（店舗の情報／営業日／営業時間／ご来店の目的／スタッフと技能／設備と点検／Web予約の公開／端末）を
  すべて開き、**各パネルの `input` / `select` / `button` / `role=switch` を DOM から全件抽出**
- 営業日の暦セルを DOM レベルで検査（火曜が押せるのか）
- 営業時間の保存・不正値（閉店 < 開店）の検証を実際に実行

## 総評 — **50 / 100**

入力の検証（閉店が開店より前なら保存を止め、理由を日本語で言う）や、
「最後に直したのは 2026年8月20日（木）　山田 大輔（店長）」の履歴表示など、
**部分的には非常に良く出来ている**。
しかし**オーナーの「火曜日に固定」は完全に事実**で、しかも原因は思ったより深い。
営業日の暦で**火曜日のセルだけ `<button>` ではなく `<span>` で描かれており、押しても何も起きない**。
「毎週のお休み」「臨時のお休み」「曜日ごとの営業時間の上書き」は
**表示されているだけで編集する手段が 1 つも無い**。
つまり「見えているのに直せない設定」がこの画面の中心にいくつも居座っている。

## 所見一覧

### SET-01 火曜日のセルだけ押せない（定休日を臨時に開けられない）
- **重大度**: **S1**
- **画面**: 設定 › 営業日
- **再現**: 8月4日（火）のセルを押す。画面の説明には
  「**丸をおすと、営業日とお休みが入れ替わります。**」と書いてある。
- **いま起きること**: **何も起きない。** DOM を見ると火曜だけ要素の種類が違う:
  ```html
  <!-- 営業日（押せる） -->
  <button type="button" data-date="2026-08-05" data-state="open" aria-label="8月5日（水） 営業">…</button>
  <!-- 火曜（押せない） -->
  <span data-date="2026-08-04" data-state="weekly-closed">…<span>8月4日（火） 定休日</span></span>
  ```
  実測でも、暦に並ぶ **52 個のボタンに火曜は 1 つも含まれない**。
  `<span>` なのでフォーカスも当たらず、キーボードからも到達できない。
  `aria-disabled` すら無いので、支援技術には「ただの文字」に見える。
  結果、**年末年始・祝日・催事など「今週の火曜だけ開ける」が絶対にできない**。
  逆に「今週の火曜だけ休む」も、そもそも既に休みなので操作の対象外。
- **あるべき姿**: 定休日のセルも押せて「この日だけ営業する」に切り替えられる。
  押せないなら、なぜ押せないかを言い、どこへ行けば直せるかを示す。
- **根拠**: 実測（DOM の `outerHTML`）、`src/web/settings/CalendarPanel.tsx`、
  `shots/settings/02-eigyoubi.png`
- **直し方の案**: `weekly-closed` のセルも `<button>` にし、押すと
  `data-state="open-exception"`（この日だけ営業）へ遷移させる。
  週の定休と、その日だけの例外は別の状態として持つ。
- **見積り**: M

### SET-02 「毎週のお休み」を変える手段が無い
- **重大度**: **S1**
- **画面**: 設定 › 営業日 ›「まとめて決める」
- **いま起きること**: 「毎週のお休み　**火曜日**」と表示されるだけ。
  実測で、営業日パネルにあるボタンは**暦の日付セルと「変更を捨てる」「保存」の 2 つだけ**。
  曜日を選ぶ `select` も、チェックボックスも、編集ボタンも**存在しない**。
  定休日を水曜に変えたい店は、この製品では**設定できない**。
- **根拠**: 実測（営業日パネルの全ボタン一覧に該当なし、`input`/`select` が **0 件**）
- **直し方の案**: 曜日 7 つのトグル（複数選択可）を置く。
  変更したときの影響（既にその曜日に入っている予約は何件か）を `ImpactCard` で見せる。
- **見積り**: M

### SET-03 「臨時のお休み」を足す・消す手段が無い
- **重大度**: **S1**
- **画面**: 設定 › 営業日 ›「まとめて決める」
- **いま起きること**: 「臨時のお休み　9月30日（水）　棚卸しのため」と 1 件表示されるだけで、
  追加・編集・削除のボタンが無い（実測）。理由（棚卸しのため）を書く欄も無い。
  暦のセルを押せば個別に休みには出来るが、**理由を残せない**ので、
  あとから「なぜこの日が休みなのか」が誰にも分からない。
- **直し方の案**: 「＋ 臨時のお休みを足す」（日付範囲＋理由）と、各行の編集・削除。
- **見積り**: M

### SET-04 曜日ごとの営業時間の上書きが読み取り専用
- **重大度**: **S1**
- **画面**: 設定 › 営業時間
- **いま起きること**: 「曜日ごとの上書き」は `<fieldset>` の中が**全部 `<span>`**:
  ```html
  <fieldset><legend>曜日ごとの上書き</legend><ul>
    <li><span>火曜日</span><span>お休み（定休日）</span></li>
    <li><span>金曜日</span><span>11:00–20:00</span></li>
    <li><span>日曜日</span><span>10:00–18:00</span></li>
    <li><span>月・水・木・土曜日</span><span>通常どおり</span></li>
  </ul></fieldset>
  ```
  編集できるのは**「通常の営業時間」の開店・閉店の 1 組だけ**。
  金曜を 11:00–20:00 から変えることも、土曜に上書きを足すことも出来ない。
  「金曜だけ 21 時まで」を設定した店が、それを元に戻せない。
- **根拠**: 実測（`outerHTML`）、`src/web/settings/HoursPanel.tsx`、`shots/settings/04-hours.png`
- **直し方の案**: 7 曜日ぶんの行にして、それぞれ「通常どおり／お休み／個別に指定」を選べるようにする。
- **見積り**: M

### SET-05 「この店舗で予約を受け付ける」が押せず、理由も直し方も無い
- **重大度**: S2
- **画面**: 設定 › 営業日
- **いま起きること**: `role="switch"` が `aria-checked="true" aria-disabled="true"` で、
  横に「**いまは切り替えられません。**」とだけ出る。
  **なぜ切り替えられないのか、どうすれば切り替えられるのか**が書いていない。
  「録音できません」の画面（`findings/recording.md` REC-07）が 3 ステップの直し方まで書いているのと対照的。
- **根拠**: 実測（`aria-disabled="true"`）
- **直し方の案**: 条件を明記する（「本日ご予約が 12 件入っているため止められません」など）。
- **見積り**: S

### SET-06 スタッフ・設備・目的を消せない
- **重大度**: S2
- **画面**: 設定 › ご来店の目的／スタッフと技能／設備と点検
- **いま起きること**: 3 パネルとも「＋ …を足す」はあるが、**削除・無効化のボタンが実測で 0 件**。
  退職したスタッフ、廃棄した測定機、やめたメニューが一覧に残り続ける。
  （スタッフには「いま使える／使えます」のスイッチがあるので無効化は出来るが、
  設備と目的には相当するものが見当たらない）
- **根拠**: 実測（各パネルのボタン一覧）
- **直し方の案**: 各行に「使わなくする」を置く。過去の予約が参照しているので物理削除はしない。
- **見積り**: M

### SET-07 端末の暗証番号が 1 欄だけ（確認入力も方針表示も無い）
- **重大度**: **S1**
- **画面**: 設定 › 端末
- **いま起きること**: `<input type="password">` が **1 つだけ**。
  - 確認用の再入力欄が無い → **打ち間違えたまま保存すると、その端末に誰も入れなくなる**
  - 4〜6 桁という制約も、「ゾロ目・連番は避ける」といった注意も画面に出ない
  - 現在の PIN を求めない（その端末を触れる人なら誰でも変えられる）
  - 変更後に何が起きるか（他の端末はどうなるか、いま業務中の人は落ちるか）の説明が無い
- **根拠**: 実測（端末パネルの `input` 一覧）
- **直し方の案**: 現在の PIN → 新しい PIN → もう一度 の 3 段にし、
  桁数と使えない並び（1234・0000 など）を入力中に判定して出す。
  保存前に「この端末は次回から新しい番号になります」と確認する。
- **見積り**: M

### SET-08 【良い点】入力の検証と、直し方の提示
- **重大度**: —（維持すべき基準）
- **観測**: 営業時間で閉店を開店より前（09:00）にすると、
  - 「保存」が自動で `disabled` になり
  - 「**閉店が開店より前のため保存できません。閉店の時刻を直してください。**」
  - 「受付を止める時間帯が営業時間の外にあるため保存できません。時間を直してください。」

  と、**何が悪いか・どうすれば直るか**を 2 件とも日本語で言う。
  さらに「木曜日に最後にお受けできるのは 18:20 です」という**導出結果の予告**まで出る。
  この水準を営業日・端末・目的の各パネルにも広げるべき。
- **根拠**: 実測、`shots/settings/06-invalid.png`

### SET-09 変更の影響（ImpactCard）が既存予約に触れない
- **重大度**: S2
- **画面**: 設定 全般
- **いま起きること**: `ImpactCard.tsx` は実装されているが、
  営業時間を 19:00 → 20:00 に変えたときに「既に入っている予約が何件どうなるか」は出なかった。
  設定変更が**過去に取った予約とどう干渉するか**が読めない。
  営業時間を短くしたら、その外にある予約はどうなるのか？ 画面は何も言わない。
- **根拠**: 実測（`shots/settings/05-dirty.png`）
- **直し方の案**: 保存前に「この変更で 8月28日 18:40 の 2 件が営業時間の外になります」と件数と一覧を出す。
- **見積り**: M

### SET-10 保存の単位がパネルごとで、離脱時の警告が確認できない

### SET-12 設定項目そのものが業務に足りない
- **重大度**: S2
- **観測**: 8 パネルを通しても、次が見当たらなかった:

- **直し方の案**: トレタの店舗設定を基準に、上記を「予約の受け方」パネルとして 1 面足す。
