# reception（来店受付）— 実機監査所見

環境: `vite preview` :4312（使い捨て D1 + seed、本日 8/27 に予約 12 件）／
Playwright Chromium 1194×834／時刻を JST 2026-08-27 11:08 に固定。実装は `src/web/reception/`。

## 監査した画面・経路
- 来店受付ボード（「ご来店中」「本日すべて」タブ、空状態）
- ウォークイン受付パネル（`＋ ご来店を受け付ける` → 台帳に重なる右ペイン）
- **予約客のチェックイン**（台帳の詳細 →「ご来店を受け付ける」）をネットワークトレース付きで実行
- 予約詳細の 3 ボタン（受付・変更・取り消し）の総当たり検証

## 総評 — **25 / 100**（RECEP-03 撤回により +5）

**この領域には、製品全体でいちばん重い欠陥がある。**
予約台帳で予約を開いて出る**主要な 3 つのボタン
「ご来店を受け付ける」「変更する」「取り消す」が、3 つとも完全に無反応**である。
`disabled` でもなく、押すと沈む見た目でもなく、通信も 1 本も飛ばない。
オーナーの「予約枠をクリックしても何も起きない」は、
**枠のクリックではなくその先のボタンで起きていた**のが実態である。

さらに来店受付ボードは 1194×834 の画面に見出し 1 行とボタン 1 つだけで、
**本日 12 件の予約が入っているのに「まだどなたもお着きになっていません」しか出ない**。
「ご来店中／本日すべて」のタブは、押しても表示が 1 文字も変わらない。

## 所見一覧

### RECEP-01 予約詳細の 3 つのボタンがすべて無反応（配線漏れ）
- **重大度**: **S1（最優先）**
- **画面**: 予約台帳 › 予約ブロック › 詳細ポップオーバー
- **再現**: 台帳で「田中 花子 様 11:00–12:00」を押し、
  「ご来店を受け付ける」／「変更する」／「取り消す」のどれかを押す。
- **いま起きること**:

  | ボタン | `disabled` | 押した結果 | 通信 |
  |---|---|---|---|
  | ご来店を受け付ける | false | **❌ 画面が 1 文字も変わらない** | **0 本** |
  | 変更する | false | **❌ 何も起きない** | 0 本 |
  | 取り消す | false | **❌ 何も起きない** | 0 本 |

  console エラーも出ない。**押した手応えすら無い**（`active:` が無いため）。

  **原因は 1 ファイルの配線漏れ**。`ReservationDetail` は 3 つのハンドラを
  すべて**任意（`?`）**で受け取る:
  ```ts
  // ReservationDetail.tsx:70-72
  onCheckIn?: () => void
  onChange?: () => void
  onCancel?: () => void
  ```
  そして `LedgerScreen` は**そのどれも渡していない**:
  ```tsx
  // LedgerScreen.tsx:449-457
  <ReservationDetail
    detail={detail} phase={detailPhase} staffName={staffName}
    equipmentNames={equipmentNames} anchor={anchor} isOffline={offline}
    onClose={() => setOpenId(null)}
  />   {/* onCheckIn / onChange / onCancel / recording が無い */}
  ```
  結果 `onClick={undefined}` になる。**任意プロパティなので TypeScript も気付けない。**
  `App.tsx:699` は `onOpenCheckin={(id) => navigate('reception', id)}` を
  `LedgerScreen` まで渡しているので、**LedgerScreen が下へ流すだけで直る**。
- **あるべき姿**: 営業時間中にいちばん押されるボタンである。押せば受付画面へ進む。
- **根拠**: 実測（3 ボタンとも本文差分なし・非 GET 通信 0 本）、
  `src/web/ledger/ReservationDetail.tsx:70-72,260-267`、
  `src/web/ledger/LedgerScreen.tsx:449-457`、`src/web/App.tsx:699`
- **直し方の案**:
  1. `LedgerScreen` から `onCheckIn` / `onChange` / `onCancel` を渡す（数行）。
  2. **再発を防ぐため、この 3 つを任意ではなく必須プロパティにする。**
     ボタンを描くのにハンドラが無い状態を型で不可能にする。
  3. 「押しても何も起きないボタンが 1 つも無い」ことを検証する e2e を足す。
- **見積り**: **S（配線）／ M（型の見直しと再発防止テスト込み）**

### RECEP-02 「これから来る人」を、承認済みの仕様そのものが持っていない
- **重大度**: **S1**（ただし実装の欠陥ではなく **spec 変更**の案件。当初「配線漏れ・見積り M」としたのは誤り）
- **画面**: 来店受付
- **いま起きること**: 1194×834 の画面に出るのは
  「2026年8月27日（木）　ご来店中 0名」「ご来店中のお客様はいません」
  「まだどなたもお着きになっていません。」「＋ ご来店を受け付ける」の 4 要素だけで、
  画面の 9 割が空白。本日 12 件の予約が入っていても 1 件も出ない。
- **これは作り忘れではない**。`worker/domain/visit-board.ts:414-421` に理由が明記されている:
  > **まだお着きでない行は盤面に出さない。**絞らないと 16:00 のご予約が 11:08 の
  > 「ご来店中 N名」に混ざる（AC-RECEP-11 の人数が来店の数でなくなり、
  > AC-RECEP-27 の「まだどなたもお着きになっていません」は当日にご予約が 1 件でもあれば二度と出ない）。

  承認済みモック `RECEPTION-JOURNEY.png` も、来ている 4 名だけを描いている。
  **この製品は仕様の段階で「これから来る人」という概念を持っていない。**
- **あるべき姿**: 受付に立つ人が知りたいのは「いま居る人」と「これから来る人」の両方である。
  盤面を 3 段（これから／いま居る／お帰り）に変える。
  ただし AC-RECEP-11 の人数の定義と AC-RECEP-27 の空状態の文言が変わるので、
  **UI 改善ではなく `SPEC_WORKFLOW.md` を通す spec 変更**として扱う。
- **回避策（先に効く）**: 同じ情報は `ledger/ReservationList.tsx:190-213` の
  「これから」チップとして**すでに動く形で存在する**。
  来店受付の空状態から、その絞り込み済みの一覧へ 1 タップで行けるようにするだけでも、
  受付に立つ人の困りごとの大半は消える。
- **根拠**: 実測、`shots/reception/02-today-all.png`、`worker/domain/visit-board.ts:414-421`、
  `specs/glasses_management/design/01-requirements.md`（AC-RECEP-11 / AC-RECEP-27）
- **見積り**: L（spec 変更を含む）／回避策だけなら S

### RECEP-03 【撤回】「本日すべて」タブが機能していない
- **重大度**: ~~S1~~ → **撤回（2026-09-03）**
- **撤回の理由**: 診断が誤っていた。タブは正しく動いている。
  実測で API 呼び出しが `scope=active` → `scope=all` に切り替わり、
  `aria-pressed` も正しく反転する（`ReceptionScreen.tsx:68,90`）。
  画面が変わらなかったのは、seed の 8/27 に来店記録が 1 行も無く、
  `all` でも `isPresent` の判定で全行が落ちるためである（RECEP-02 と同じ仕様）。
  クリック前後の画面テキストが一致したことだけを見て「タブが死んでいる」と断じたのが誤り。
- **残る論点**: 両タブとも空のときに、どちらを選んでいるのかが本文から読めない。
  見出しの「ご来店中 0名」がタブに追随せず、`all` を選んでも「ご来店中」のままである。

### RECEP-04 ウォークイン受付が台帳へ画面ごと飛ぶ
- **重大度**: S2
- **画面**: 来店受付 ›「＋ ご来店を受け付ける」
- **いま起きること**: 押すと**予約台帳の画面へ切り替わり**、その右に 400px の受付パネルが重なる。
  上バーの見出しも「来店受付」から「予約台帳」に変わる。
  受付をしている最中に自分がどの画面に居るのか分からなくなる。
  やめると台帳に取り残され、来店受付には戻らない。
- **あるべき姿**: 受付は来店受付の画面の中で完結する（空き状況が要るなら盤を埋め込む）。
- **根拠**: 実測、`shots/reception/03-walkin.png`
- **見積り**: M

### RECEP-05 【良い点】ウォークイン受付パネルの作り
- **重大度**: —
- **観測**: 「店頭のお客様を受け付けます」「いまお待ち 0名」「ウォークイン 001」の番号、
  ご用件 4 択（所要時間つき）＋「4 択にないご用件」、
  「電話番号で探す（下4桁でも探せます）」＋「あとで登録する」、
  そして「受付して台帳に載せる」が用件を選ぶまで押せない ——
  **名前が分からない状態でも受付を始められる**という業務の現実に合っている。
  この設計思想を来店受付ボード本体にも広げるべき。
- **根拠**: `shots/reception/03-walkin.png`

### RECEP-06 待ち時間・順番・進行状況の概念が無い
- **重大度**: **S1**
- **画面**: 来店受付
- **いま起きること**: 出るのは「ご来店中 N名」という人数だけ。
  - 何分待っているか
  - 誰の番か（呼び出し）
  - いま何をしている段階か（受付済／案内中／検査中／フレーム選び／お会計）
  - 担当が付いているか

  が一切無い。台帳の最下段にも「ご来店お待ち 0名」という行があるが、
  ここも人数だけで、押せない（`findings/ledger-calendar.md` LEDGER-13）。
- **あるべき姿**: お客様 1 人ずつのカードに、お着きの時刻・経過時間・段階・担当を出し、
  段階を進めるボタンを置く。待ち時間が閾値を超えたら色を変える。
- **見積り**: L

### RECEP-07 受付の取り消し・やり直しの導線が無い
