# customers（顧客台帳）— 実機監査所見

環境: `vite preview` :4315（使い捨て D1 + seed、お客様 46 名）／Playwright Chromium 1194×834／
時刻を JST 2026-08-27 11:08 に固定。実装は `src/web/customers/`、スキーマは
`src/worker/db/schema.ts:762`。

## 監査した画面・経路
- 顧客台帳 一覧（並べ替え・絞り込み・検索欄・ページング）
- 新規お客様登録の入力欄を DOM から全件抽出
- 要約ペイン → くわしく見る → 内容を直す → この方のご予約を取る を実際に押して結果を観測
- `customers` テーブルの列定義

## 総評 — **25 / 100**

**オーナーの「顧客情報も全然入力できる内容が少ない」は、想定よりはるかに深刻**。
新規登録で入力できるのは **お電話番号・お名前・ふりがな の 3 つだけ**。
DB には `email` / `birth_date` / `address` / `memo` の列があるのに、**画面から入れる手段が無い**。
そして決定的なのは、**お客様の情報を編集する画面が存在しない**こと ——
「内容を直す」を押すと「**お客様の情報を直す画面はこれから作ります。**」と出る。
つまり**一度登録したお客様は、電話番号の打ち間違いすら直せない**。
画面には「いまの度数」「いまお使いのメガネ」「注意ごと」という眼鏡店らしい枠が用意されているが、
**すべて「記録はまだありません」で、入力する導線が 1 つも無い**。器だけがある。

## 所見一覧

### CUST-01 お客様の情報を編集する画面が存在しない
- **重大度**: **S1**
- **画面**: 顧客台帳 › くわしく見る ›「内容を直す」
- **再現**: 任意のお客様を開き、「内容を直す」を押す。
- **いま起きること**: 画面に「**お客様の情報を直す画面はこれから作ります。**」と出るだけ。
  入力欄は **0 件**（実測）。
  電話番号の打ち間違い、結婚による改姓、引っ越し、いずれも**一切直せない**。
  一覧の「覚えておくこと」（memo）も編集できない。
- **根拠**: 実測（クリック前後の本文差分）、`shots/customers/05-edit.png`
- **直し方の案**: 編集画面を作る。登録画面と同じ部品を再利用し、
  `version` による楽観ロックは既にスキーマにあるのでそのまま使える。
- **見積り**: M

### CUST-02 新規登録の入力欄が 3 つしかない
- **重大度**: **S1**
- **画面**: 顧客台帳 ›「＋ 新しいお客様を登録」
- **いま起きること**: 実測した `input` は **3 つだけ**:

  | 項目 | type | inputmode | autocomplete | 必須 |
  |---|---|---|---|---|
  | お電話番号 | `tel` | **`none`** | `off` | ✗ |
  | お名前 | `text` | — | `off` | ✗ |
  | ふりがな | `text` | — | `off` | ✗ |

  **メールアドレスの欄が無い**（Web 予約からしか入らない）。
  生年月日・住所・メモも DB には列があるのに入力できない。
  必須指定が 1 つも無いので、全部空のお客様が作れてしまう可能性がある。
- **根拠**: 実測（DOM 抽出）、`shots/customers/02-new.png`、
  `src/worker/db/schema.ts:770-778`（列は存在する）
- **見積り**: M

### CUST-03 眼鏡店の顧客カルテとして必要な情報がほぼ全部無い
- **重大度**: **S1**
- **画面**: 顧客台帳 全体
- **いま起きること**: `customers` テーブルが持つ実質的な項目は
  `name` / `kana` / `phone` / `email` / `birth_date` / `address` / `memo` の **7 つ**だけ。
  しかも **`memo` は 0〜60 文字**（スキーマのコメント）。お客様 1 人ぶんの自由記述が 60 字。

  詳細画面には「度数の移り変わり」「いまお使いのメガネ　0本」「注意ごと　0件」という
  節が用意されているが、**中身は全部「ありません」で、入れる手段が無い**。
  眼鏡店の台帳として、少なくとも次が要る:

  | 分類 | 足りていない項目 |
  |---|---|
  | 連絡 | メール、電話（複数）、連絡の可否、DM 可否、個人情報の同意 |
  | 基本 | 生年月日／年齢、性別、住所、職業（VDT 作業の有無） |
  | 視力 | **度数（右/左 S・C・AX・ADD・PD）**、測定日、測定者、裸眼・矯正視力の履歴 |
  | 装用 | **いまお使いのメガネ**（購入日・フレーム・レンズ・度数）、コンタクトの使用、老眼・遠近の有無 |
  | 販売 | 購入履歴、金額、保証期間、修理履歴、次回買い替え目安 |
  | 接客 | 担当スタッフ、好みのフレーム、予算感、紹介元・来店動機 |
  | 注意 | アレルギー、装用上の注意、要配慮（車椅子・お子様連れ・お急ぎ）、NG 事項 |
  | 集計 | 来店回数・最終来店（**これはある**）、累計購入額、離反リスク |

- **根拠**: `src/worker/db/schema.ts:762-802`、`shots/customers/04-detail-full.png`
- **直し方の案**: `customer_prescriptions` / `customer_eyewear` / `customer_notes` の
  3 テーブルを足し、詳細画面の既存の 3 節にそのまま流し込む（器は既にある）。
  `memo` の 60 字制限を外し、複数件の「注意ごと」に置き換える。
- **見積り**: L

### CUST-04 一覧に電話番号の列が無い
- **重大度**: **S1**
- **画面**: 顧客台帳 一覧
- **いま起きること**: 列は **お名前／ご来店／最後のご来店／覚えておくこと** の 4 つ。
  電話予約が主な業態なのに、**一覧から電話番号が読めない**。
  折り返しの電話をかけるには、行を選び → 要約を見て（そこにも電話は出ない）→
  「くわしく見る」まで **2 回**進む必要がある。
  しかも電話番号はただのテキストで、`tel:` リンクになっていない。
- **根拠**: 実測、`shots/customers/01-list.png` / `04-detail-full.png`
- **直し方の案**: 一覧に電話番号列を足す。詳細の電話番号を `tel:` リンクにする。
- **見積り**: S

### CUST-05 一覧が 8 件ずつのページングで、46 名を見るのに 5 回押す
- **重大度**: S2
- **画面**: 顧客台帳 一覧
- **いま起きること**: `role="option"` の実測数は **8**。
  下に「ほか 38名／続きを見る ›」。1 画面 8 件は、834px の iPad で
  **右ペイン 360px を空白のまま遊ばせながら**の 8 件である。
  お客様が数千人になる実運用では、この一覧はほぼ使えない。
- **根拠**: 実測（`option` 8 件）、`src/web/customers/CustomerList.tsx:440`（`PAGE_ROWS`）、
  `shots/customers/01-list.png`
- **直し方の案**: 行の高さを詰め、スクロールで続きを読み込む（無限スクロール）。
  右ペインは選択前も「今日ご来店予定のお客様」などで埋める。
- **見積り**: M

### CUST-06 要約ペインに電話番号も次回予約の詳細も出ない
- **重大度**: S2
- **画面**: 顧客台帳 › 行を選んだときの右ペイン
- **いま起きること**: 出るのは 名前／かな／お客様番号／次のご予約／いまの度数／
  いまお使いのメガネ／注意ごと の 7 行で、**5 つが「ありません」**。
  行を選んで最初に見えるのが「ありません」の羅列で、業務の役に立たない。
- **根拠**: `shots/customers/03-detail.png`
- **直し方の案**: 電話番号・来店回数・最終来店・前回のご用件・担当を先に出す。
- **見積り**: S

### CUST-07 電話番号欄が `inputmode="none"`・全欄 `autocomplete="off"`
- **重大度**: S2
- **画面**: 新規登録
- **いま起きること**: `booking.md` BOOK-11 と同じ。
  画面内テンキー前提で `inputmode="none"` にしているため、
  外付けキーボードやソフトウェアキーボードからの入力ができない。
- **見積り**: S

### CUST-08 顧客の削除・非表示・統合の導線が画面に無い
- **重大度**: S2
- **画面**: 顧客台帳
- **いま起きること**: 詳細画面のボタンは
  「‹ お客様の一覧へ戻る」「内容を直す」「この方のご予約を取る」の **3 つだけ**（実測）。
  `CustomerMerge.tsx` / `CustomerMatch.tsx` は実装されているのに、
  **一覧・詳細のどちらからも到達できない**。
  seed には「田中 一郎 様　ご家族で同じお電話番号」という
  まさに名寄せが要る行が入っているのに、そこから統合へ行けない。
- **根拠**: 実測（詳細のボタン一覧）
- **直し方の案**: 詳細に「別のお客様と同じ方かも」→ 統合、「使わなくする」を足す。
- **見積り**: M

### CUST-09 【良い点】検索と一覧の言葉づかい
- **重大度**: —
- **観測**: 検索欄の「**お名前・電話番号　一部でも探せます**」、
  来店回数の「**初**」表示、「覚えておくこと」という列名、
  `role="option"` の読み上げ名が「相川 みどり 様　あいかわ みどり　ご来店 2回　最後のご来店 2026年7月3日　調整の途中です」と
  1 行で全部読めるようになっている点は良い。
  並べ替え（お名前順／ご来店の回数順）と絞り込みもある。
