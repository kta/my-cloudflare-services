# booking（予約を取る）— 実機監査所見

環境: `vite preview` :4311（使い捨て D1 + seed）／Playwright Chromium 1194×834（iPad 横）／
時刻を JST 2026-08-27 11:08 に固定。実装は `src/web/booking/`。

## 監査した画面・経路
- 工程1 日時（暦 14 日ぶん・時刻の札）／工程2 ご来店の目的・所要時間／工程3 担当と場所（SlotBoard）／
  工程4 お客様／工程5 ご確認 の導線を実機で通した
- **枠のドラッグを実マウス操作（`page.mouse.down/move/up`）で 4 通り検証**（帯本体・ハンドル・Esc・キーボード）
- 空き枠 API（`/api/staff/availability`）の生応答と、画面に出た札の数を突き合わせ
- 入力欄の `type` / `inputmode` / `autocomplete` / `required` を DOM から抽出

## 総評 — **40 / 100**

工程の分け方・読み上げ文・アクセシブル名（「8月28日（金）　定休」など）は丁寧で、
ここは他の画面より作り込まれている。しかし**予約枠を動かす操作が 44×44px の
「⠿」ハンドルだけに縛られており、帯の本体をつかんでも 1px も動かない**。
これはオーナーの指摘そのもので、実測でも帯の面積の **30.6% しか掴めない**。
加えて Esc で取り消せず、キーボードでは一切動かせない。
さらに暦が **14 日ぶんしか無く**（月移動が無い）、
工程1 の時刻の札は 18 枠あるうち **8 枠だけを出して残り 10 枠を折りたたむ**。
その 10 枠には 15:00〜19:00 の**午後と夕方が丸ごと**含まれる。

## 所見一覧

### BOOK-01 予約枠は「⠿」ハンドルでしか掴めない（帯の本体は反応しない）
- **重大度**: **S1**
- **画面**: 工程3 担当と場所（SlotBoard）
- **再現**: 13:00 の「このご予約」の緑の帯を、**⠿ 以外の場所**でつかんで右へ 200px 動かす。
- **いま起きること**: 実マウス操作での実測結果:

  | 操作 | 結果 |
  |---|---|
  | 帯の**本体**（中央）をドラッグ | ❌ **動かない**（13:00–14:00 のまま） |
  | **⠿ ハンドル**をドラッグ | ✅ 14:00–15:00 へ動く |
  | ドラッグ中に **Esc** | ❌ 取り消せない（14:00 で確定したまま） |
  | ハンドルにフォーカスして**矢印キー** | ❌ 何も起きない |

  帯は 144×44px、ハンドルは 44×44px。**掴める面積は帯全体の 30.6%**。
  コード上も `onPointerDown` は `PlacedBand` の中の `<button>` にしか付いていない:
  ```tsx
  // SlotBoard.tsx:435-441
  <button type="button" aria-label={`ご予約をつかんで動かす　${placedLabel}`}
    onPointerDown={onGrab} className="... min-h-11 min-w-11 ...">
    <span aria-hidden="true">⠿</span>
  </button>
  ```
  しかも ⠿ は薄いグレーの点で、スクリーンショットで見ても**そこが掴みしろだと分からない**。
- **あるべき姿**: 帯のどこを掴んでも動く。Google カレンダーもトレタも、
  予定のブロック全体がドラッグ対象で、端だけがリサイズ用。
  ハンドルは補助であって唯一の入口にしてはいけない。
- **根拠**: `src/web/booking/SlotBoard.tsx:435-441`、実測（上表）、
  `shots/booking/04-slotboard.png`（⠿ が視認できない）
- **直し方の案**: `onPointerDown` を `PlacedBand` のルート要素へ移し、
  帯全体を掴めるようにする（⠿ は「掴める」ことを示す装飾として残す）。
  帯の左右端 8px は将来のリサイズ用に予約しておく。
- **見積り**: S

### BOOK-02 ドラッグを Esc で取り消せない
- **重大度**: **S1**
- **画面**: 工程3 SlotBoard
- **再現**: ⠿ を掴んで動かしている途中で Esc を押し、そのまま指を離す。
- **いま起きること**: Esc は無視され、離した位置で確定する（14:00–15:00 になる）。
  戻すには右ペインの「もとの 13:00 に戻す」を探して押すしかない。
- **あるべき姿**: ドラッグ中の Esc で必ず元の位置へ戻る。HIG でも、
  ドラッグは離すまで取り消せるのが約束事。
- **根拠**: `src/web/booking/SlotBoard.tsx:235-237`（`onPointerMove` / `onPointerUp` / `onPointerCancel` のみ。
  `keydown` を見ていない）、実測 (C)
- **直し方の案**: ドラッグ開始時に `window.addEventListener('keydown')` を張り、
  Escape で `onDragEnd` を「元へ戻す」経路で呼ぶ。
- **見積り**: S

### BOOK-03 キーボードだけでは予約枠を動かせない
- **重大度**: S2（アクセシビリティ）
- **画面**: 工程3 SlotBoard
- **いま起きること**: ハンドルは `<button>` でフォーカスは当たるが、
  矢印キー・Enter・Space のいずれにも反応しない（実測 (D)）。
  ポインタを使えない利用者には**予約時刻を変える手段が無い**。
- **あるべき姿**: フォーカス中に Enter/Space で「つかむ」モードに入り、矢印キーで移動、
  Enter で確定、Esc で取り消し。移動のたびに `aria-live` で
  「小林 学 14:00–15:00 に移動しました」と読み上げる。
- **根拠**: `src/web/booking/SlotBoard.tsx:437`（`onKeyDown` が無い）、実測 (D)
- **直し方の案**: 上記のキーボードドラッグを実装。`slot-drag.ts` の純関数がそのまま使える。
- **見積り**: M

### BOOK-04 暦が 14 日ぶんしか無く、月を動かせない
- **重大度**: **S1**
- **画面**: 工程1 日時
- **再現**: 「来月の 20 日で」と言われたつもりで、その日を選ぼうとする。
- **いま起きること**: 暦に出るのは **8/24〜9/6 の 14 日だけ**（実測）。
  前月・翌月へ動かすボタンが無く、日付を直接入力する欄も無い。
  **2 週間より先の予約は、この画面からは 1 件も取れない**。
  見出しは「2026年8月」固定なので、9/1〜9/6 の札が 8 月として表示されている。
- **あるべき姿**: 月送りと、少なくとも「何日先まで受け付けるか」の設定範囲すべてを選べること。
  眼鏡店は「できあがりのお受け取り」で 2〜3 週間先を普通に取る。
- **根拠**: 実測（暦のボタン 14 個のみ）、`src/web/booking/DateTimeStep.tsx:62` のコメント
  「暦の中は同じ 2 週」、`shots/booking/02b-slots.png`
- **直し方の案**: 月表示＋前後移動、または「2週間 / 1か月 / 3か月」の切り替え。
  見出しの月は表示中の日付から出す。
- **見積り**: M

### BOOK-05 時刻の札が既定で 8 枠に切られ、午後と夕方が隠れる
- **重大度**: **S1**
- **画面**: 工程1 日時
- **再現**: 8/28（金）を選ぶ。
- **いま起きること**: API は **18 枠**（11:00〜19:30）を返しているのに、
  画面に出るのは **8 枠（11:00〜14:30）**だけ。残り 10 枠は
  「ほかの時刻も見る（あと10件）」を押さないと出ない。
  隠れているのは **15:00 / 15:30 / 16:00 / 16:30 / 17:00 / 17:30 / 18:00 / 18:30 / 19:00** ——
  つまり**午後と夕方が丸ごと**。
  スクリーンショットではその折りたたみボタンの下に **180px の空白**があり、
  10 枠を出す余地は十分にある。
  電話口で「11時は満席、11時半、13時、13時半、14時、14時半が空いています」と読み上げると、
  一番予約が入りやすい夕方を**一度も案内しない**ことになる。
- **根拠**: 実測（API 18 枠 vs UI 8 枠）、`src/web/booking/DateTimeStep.tsx:55`（`SLOT_WINDOW = 8`）、
  `shots/booking/02b-slots.png`
- **直し方の案**: 既定を「営業時間ぶん全部」にし、縦に入りきらないぶんはスクロールさせる
  （親は既に `overflow-y-auto`）。窓を残すなら「午前／午後／夕方」のタブにする。
- **見積り**: S

### BOOK-06 休憩・営業時間外の枠を「満席」と表示している
- **重大度**: **S1**
- **画面**: 工程1 日時
- **再現**: 8/28 の 11:00 / 12:00 / 12:30 の札を見る。
- **いま起きること**: 画面には **「満席」**と出るが、API の `reason` は 3 枠とも **`break`**（休憩）。
  19:30 の枠も `outside_hours` なのに「満席」になる。
  コードにも「受け付けられない枠は理由を問わず『満席』と書く」とある
  （`DateTimeStep.tsx:371`）。
  **アルバイトはこれを読んで、お客様に「その時間は満席です」と嘘を伝える**。
  実際は休憩なので、店長判断で受けられるかもしれないし、
  「12時台は休憩をいただいています」と言えば納得も得られる。
- **あるべき姿**: 理由ごとに言葉を変える（満席／休憩中／営業時間外／お休み）。
  `slot-drag.ts` の `blockedText()` は既に理由別の日本語を持っているので、
  同じ語彙を工程1 でも使う。
- **根拠**: 実測（API `reason:"break"` → UI「満席」）、
  `src/web/booking/DateTimeStep.tsx:371,385`、`src/web/booking/slot-drag.ts:69-80`
- **直し方の案**: `Slot` の `note` を `reason` で分岐させる。
- **見積り**: S

- **見積り**: S

### BOOK-10 お客様の入力項目が 4 つしかない
- **重大度**: **S1**
- **画面**: 工程4 お客様
- **いま起きること**: 入力できるのは **お電話番号 / お名前 / ふりがな / ご要望・伝言** の 4 つだけ（実測）。

  ご要望・DM 可否くらいは 1 画面で。既存客なら電話番号を打った時点で候補が出る。
- **根拠**: 実測（`input` の抽出結果）、`shots/booking/08-customer.png`
- **直し方の案**: 顧客台帳の項目拡張（`customers.md` 参照）と歩調を合わせ、
  この画面は「電話番号で既存客を引く → 見つかればカルテを開く／無ければ新規」を主導線にする。
- **見積り**: M

### BOOK-11 電話番号欄が `inputmode="none"`・全欄 `autocomplete="off"`
- **重大度**: S2
- **画面**: 工程4 お客様
- **いま起きること**: お電話番号は `type="tel"` だが `inputmode="none"` が付いており、
  **iPad のソフトウェアキーボードが出ない**（画面内のテンキーを使う前提）。
  外付けキーボードや Bluetooth キーボードを使う店では入力手段が消える。
  4 欄すべて `autocomplete="off"` なので、iPad の予測入力・連絡先からの補完も効かない。
- **根拠**: 実測（DOM 属性の抽出）
- **直し方の案**: 画面内テンキーは残しつつ `inputmode` は `tel` にする（両方使えるのが正しい）。
  氏名・カナには `autocomplete="name"` / `honorific-prefix` 相当を付ける。
- **見積り**: S
