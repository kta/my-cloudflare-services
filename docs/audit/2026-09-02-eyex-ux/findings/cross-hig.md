# cross-hig（操作感・モーション・アクセシビリティ・情報設計）— 横断監査所見

`services/glasses_management/src/web`（.tsx 約 49k 行）全体に対する静的計測と、
11 画面の実機計測（Playwright）を突き合わせた横断所見。

## 総評 — **25 / 100**（HIG-01 の訂正により +5）

オーナーの「**HIG に準拠しているならぬるぬるした感じというか、
すごい直感的に全てが動かせるはずだと思って使っていましたが、全然そんなことはなかった**」は、
計測すると原因が 1 つの数字に集約される ——
**この製品には CSS トランジションが 1 つも存在しない**。
`transition` の記述が **0 件**、`hover:` が **0 件**、`animate-*` が **2 件**。
デザイントークン（`packages/ui/src/theme.css`）にも duration / easing のトークンが 1 つも無い。
色・寸法・書体・フォーカスリング・タップ標的は丁寧に設計されているのに、
**「時間」という次元だけが設計されていない**。

## 所見一覧

### HIG-01 手応えの定義は共有部品にあるが、255 個中 252 個のボタンがそれを使っていない
- **重大度**: **S2**（初版は「製品全体で transition 0 件」として S1 とした。**その断定は誤りだった** — 下記）
- **範囲**: 全画面

> **訂正（2026-09-03）**: 初版に「`transition` の記述が製品全体で 0 件、`hover:` が 0 件」と書いたのは誤り。
> grep の範囲を `services/glasses_management/src/web` に限り、**共有 UI パッケージを見ていなかった**。
> `packages/ui/src/components.tsx:50-55` の共有 `Button` は
> `transition-colors`（0.15s）と 3 つの `hover:` 変種を持っている。
> 実機でも設定の一部パネルで `transitionDuration: 0.15s` が観測できる。

- **正しい事実**: 手応えの定義は存在する。届いていないだけである。

  | 数えたもの | 件数 |
  |---|---|
  | 共有 `Button`（`transition-colors` と `hover:` を持つ）を描いている箇所 | **3** |
  | 素の `<button className="...">` を手書きしている箇所 | **252** |
  | `services/glasses_management/src/web` 内の `transition` 記述 | 0 |
  | 同 `hover:` | 0 |
  | 同 `active:` | 6 |
  | 同 `animate-*` | 2（`animate-spin` 1・`animate-pulse` 1） |
  | 同 `scale-` / `will-change` / `motion-reduce` | 0 |
  | `packages/ui/src/theme.css` の duration / easing トークン | **0** |
  | `focusRing` / `focusRingOnPine` の利用 | 377 |

  実機の計測でも、トップ 88 要素・予約台帳 276 要素・来店受付 74 要素・分析 114 要素・
  予約を探す 177 要素・Web予約 30 要素のいずれも `transitionDuration ≠ 0s` が **0 件**だった。
  共有 `Button` が使われている設定パネルだけが例外である。

- **なぜこうなったか**: `focusRing` は文字列としてエクスポートされているので 377 か所へ広まった。
  一方、押下の手応えは `Button` コンポーネントの中に閉じているため、
  `<button>` を手書きした 252 か所には 1 つも届かない。
  **配り方の違いが、そのまま普及率の違いになっている。**
- **あるべき姿**: HIG は操作の結果を目で追えることを求める。
  押下 100ms のフィードバック、画面遷移 200–250ms、パネルの開閉 150–200ms、
  選択状態の 120ms、そして `prefers-reduced-motion` での無効化。
- **直し方の案**:
  1. `theme.css` に `--duration-*` と `--ease-*` のトークンを足す
  2. 押下の手応えを `focusRing` と同じ**文字列**としてエクスポートする
     （`pressFeedback = 'transition-transform active:scale-[0.98]'`）。
     そうすれば `focusRing` を書いてある 377 か所に隣接して 1 語足すだけで広がる
  3. `app.css` に `@media (prefers-reduced-motion: reduce)` を置く
- **見積り**: S（トークンと文字列の追加）＋ M（377 か所への適用）

### HIG-02 押しても何も起きないボタンが 5 個ある（うち 3 個は台帳の主要操作）
- **重大度**: **S1**
- **範囲**: トップ、予約台帳の予約詳細
- **計測**: 8 画面 169 個のボタンについて React の props を実行時に調べ、
  `onClick` も `onPointerDown` も持たないものを列挙した:

  | 画面 | ボタン | ハンドラ無し |
  |---|---|---|
  | トップ | 16 | **2**（「EYEX 丸の内店へ切り替える」「EYEX 新宿店へ切り替える」） |
  | **予約台帳 › 予約詳細** | — | **3**（「**ご来店を受け付ける**」「**変更する**」「**取り消す**」） |
  | 予約台帳（本体）／来店受付／予約を探す／受付履歴／顧客台帳／分析／設定／予約を取る | 153 | 0 |

  **原因はコードベースに 2 つの流儀が混在していること。**
  安全な流儀（ハンドラが無ければボタンごと出さない）:
  ```tsx
  // ReservationList.tsx:275 / VisitBoard.tsx:175 — 正しい
  {...(onCheckin !== undefined ? { onClick: () => onCheckin(id) } : {})}
  {rows.length > 0 && onReceiveVisit !== undefined && (<button …>)}
  ```
  危険な流儀（`undefined` をそのまま `onClick` に渡す）:
  ```tsx
  // ReservationDetail.tsx:260-267 — これが壊れている
  <button type="button" disabled={isOffline} onClick={onCheckIn}>ご来店を受け付ける</button>
  ```
  任意ハンドラ（`onXxx?: () => void`）は全体で **48 個**あり、
  そのうち **`onCheckIn` は親が 1 か所も渡していない**（静的解析で確認）。
- **直し方の案**:
  1. `ReservationDetail` の `onCheckIn` / `onChange` / `onCancel` を**必須プロパティにする**
     （ボタンを描くのにハンドラが無い状態を型で不可能にする）
  2. 残り 48 個の任意ハンドラを棚卸しし、安全な流儀に揃える
  3. **「押しても何も起きないボタンがゼロ」を検証する e2e** を足す
     （本監査で使った React props の走査がそのまま使える）
- **見積り**: S（修正）＋ M（再発防止）

### HIG-03 押せるものと押せないものが見た目で区別できない
- **重大度**: **S1**
- **範囲**: 全画面（特に予約台帳・設定・Web予約）
- **計測**: `cursor-pointer` の記述は全体で **3 件**のみ。
  予約台帳の 128 個の操作可能要素のうち `cursor: pointer` を持つものは **0 件**。
- **いま起きること**: 同じ見た目の要素が、押せたり押せなかったりする:

  | 画面 | 押せそうで押せないもの |
  |---|---|
  | 予約台帳 | 空き枠 69 セル・休憩帯・行ヘッダ・列ヘッダ |
  | 設定 › 営業日 | 火曜日のセル（`<span>` で描かれている） |
  | Web予約 › 日時 | 空きの無い日のカード 6 枚 |
  | 顧客台帳 | 「内容を直す」（押すと「これから作ります」） |
  | トップ | 店舗切替チップ 2 つ |

  **「押せないものを `<span>` で描く」という共通の誤り**が 3 画面で繰り返されている。
  `<span>` はフォーカスも当たらず、`aria-disabled` も無いので、
  支援技術には「ただの文字」に見える。
- **直し方の案**: 押せない要素も `<button disabled>` か `aria-disabled` で描き、
  無効の見た目（薄い塗り・斜線）と理由（`aria-describedby`）を必ず添える。
  Web予約の主要ボタンは既にこの作法（`aria-disabled` + `aria-describedby`）なので、
  **その流儀を全画面に広げるだけでよい**。
- **見積り**: M

### HIG-04 URL が動かず、戻る・リロード・共有ができない
- **重大度**: **S1**
- **範囲**: 業務 SPA 全体 ＋ お客様向け Web 予約
- **計測**: トップ／予約台帳／来店受付／予約を探す／受付履歴／顧客台帳／分析／設定 の
  どこへ移動しても `location.href` は `http://localhost:PORT/` のまま。
  `document.title` は全画面で「**EYEX予約**」固定（Web 予約の画面でも同じ文字列）。
- **いま起きること**:
  - **ブラウザの戻るで `about:blank` になりアプリから出る**（真っ白な画面）
  - **リロードすると置き場所選択と PIN からやり直し**（入力途中は失われる）
  - 「この予約を見て」とリンクで渡せない、ブックマークできない
  - iPad の Safari で複数タブに別画面を出しておけない
  - スクリーンリーダ利用者は今どこに居るか分からない
- **直し方の案**: 画面ごとに URL を持たせる。
  併せて `document.title` を「予約台帳 8月27日（木）｜EYEX 銀座店」のように更新する。
- **見積り**: L

### HIG-06 画面がビューポートからはみ出し、続きがあることが分からない
- **重大度**: **S1**
- **範囲**: 予約台帳・予約を取る 工程3
- **計測**（1194×834）:

  | 画面 | はみ出し |
  |---|---|
  | 予約台帳 | 時刻の列 **17:00 / 17:30 / 18:00 / 18:30** と **21 個の `gridcell`** が画面外（`canScrollX: false`） |
  | 予約を取る 工程3 | 盤の 18 列中 **10 列**が画面外（「14:00から20:00」のセルは中心が x=1211） |

  スクロールできる親（`overflow-x-auto`）はあるが、
  **スクロールバーも端の影もフェードも矢印も無い**。
  さらに横へ送ると**担当者名の列（`position: static`）が一緒に流れて消える**。
- **直し方の案**: ①端に影／グラデーションで続きを示す ②名前列と時刻の見出し行を `sticky` に
  ③開いたときに現在時刻の列へ自動スクロール。
- **見積り**: M

### HIG-07 【良い点】タップ標的とフォーカスリングは全画面で満たされている
- **重大度**: —
- **計測**: 実測した全画面で **44pt 未満のタップ標的は 0 件**
  （トップ・予約台帳・設定・来店受付・分析・Web予約（390×844）すべて）。
  `focusRing` / `focusRingOnPine` は **377 か所**で使われており、
  252 個の `<button>` を十分に覆っている。
  `packages/ui/src/components.tsx` に
  「All interactive controls meet the 44px touch-target floor.」と
  `controlBase = 'min-h-11 …'` が単一ソースとして置かれている。
  フォーカスの色（`--color-focus`）は他の役割に使わない専用トークンで、
  白・下地・薄い緑の上で 5.8:1 を確保している。
- **意味**: **寸法とコントラストの設計は既に良い。足りないのは「時間」と「状態」だけ**である。

### HIG-09 同じ欠陥が複数画面で繰り返されている（部品の共有不足）
- **重大度**: S2
- **観測**: 同一の原因を持つ欠陥が、画面をまたいで独立に存在する:

  | 欠陥 | 出現箇所 |
  |---|---|
  | 時刻の札を 8 件で切る | 予約を取る 工程1、予約を探す › 日時を変える |
  | 休憩・時間外を「満席」と誤表示 | 同上 2 画面 |
  | 暦が 2 週間で切れる | 同上 2 画面 |
  | 押せない要素を `<span>` で描く | 設定 › 営業日、Web予約 › 日時、予約台帳 |
  | 盤が画面外にはみ出す | 予約台帳、予約を取る 工程3 |
  | 電話番号を出す／出さない | 取り消し画面は出す、台帳詳細・顧客一覧は出さない |
  | 名前が無いときの表示 | 「お客様 様」（検索）／時刻だけ（台帳）／表示なし（一覧） |

- **直し方の案**: 「時刻の枠を並べる部品」「空き枠の盤」「予約 1 件の表示名」
  「押せない状態の見せ方」を共有部品に切り出す。
  1 つ直せば全画面が直る形にしないと、同じ指摘が何度も出続ける。
- **見積り**: L

### HIG-11 空白の使い方が業務画面として非効率
- **重大度**: S2
- **観測**: 1194×834 の画面で、下半分〜右側が大きく空くものが多い:
  - トップ: 画面の **半分以上**が空白

  **余っている場所と足りない場所が噛み合っていない。**
- **見積り**: M
