# ジョブズの目線で見直す — 1 巡目（2026-09-04）

実機（`docs/audit/2026-09-02-eyex-ux/harness/serve.sh 4380`）を Playwright で操作し、
撮った画面を目で見て、座標と色は DOM から実測した。推測で書いたものは 1 つも無い。

サブエージェントで 12 領域を同時に見る手は 3 回試して 3 回とも API の 529 で全滅したので、
手で歩いた。歩いた画面は トップ／予約台帳／来店受付／顧客台帳／予約を探す／受付履歴／分析／設定。

## 総評

**いちばんの問題は「今日が見えないこと」。**レジ横の iPad を開いて最初に出るのは、
「新しい予約を取る」と「予約を変更する」の 2 枚のカードだけで、本文の下 265px と
右 354px が空いている。今日の予約が何件あるのか、次のご来店が何時なのか、
いま何人お待ちなのかが、この面には 1 つも書かれていない。台帳を開くまで店の状況が分からない。

承認済みモックはそうなっていない。`HOME.png` はカードの下に 8/24〜8/30 の日付を 7 つ並べ、
右端に「カレンダーから選ぶ」を置いている。**モックが正しく、実装がそれを持っていない。**

## まずこの 3 つ

### J-01 トップに「今日」が無い（S1）

- **実測**: 共有端末のトップの中身は y=205〜569 で終わる。カードは 2 枚（各 720×132、x=120、
  y=205 と y=361）、その下に店舗切替のチップが 2 つ（y=525、h=44）。下 265px は空。
- **モックとの差**: `HOME.png` はカードの下に「2026年 8月」と 月24／火25／水26／木27／金28／土29／日30 の
  7 つの札、右端に「カレンダーから選ぶ」を置く。実装（`src/web/App.tsx:919-956`）にこの帯は無い。
  代わりに置かれている店舗切替チップはモックに無い（SHELL-07 で足したもの）。
- **なぜ効くか**: この帯は飾りではなく、**トップから今日・明日の台帳へ 1 タップで入る道**である。
  いま台帳へ行くには左ナビの「予約台帳」を押し、開いた先で日付を選び直すことになる。
  そしてアルバイトの人がいちばん知りたい「今日どうなっているか」に、トップが何も答えていない。
- **直し方**: モックの週の帯を実装する。日付の札には**その日の予約件数**を添える
  （モックは日付だけだが、空いた 265px はそれを置ける）。店舗切替チップはその下へ落とす。

### J-02 お知らせへの入口が、いる場面にだけ無い（S1）

- **実測**: `src/web/shell/AppShell.tsx:173` は「お知らせ」の行き先を
  `current === 'alerts'` のときだけ左ナビに出す。つまり**お知らせを開いているときだけ
  お知らせの行が現れる**。`destinations.ts` の `DESTINATIONS` に 'alerts' は無い。
- 唯一の入口は上のバーの「お知らせ 3」だが、これは 来店受付 の面には出ない（実機で確認）。
  接客の面から通知を外す判断は分かるが、**その面から通知へ行く道が他に無い**。
- **なぜ効くか**: 3 件の未読が赤いバッジで見えていて、押しに行けない場面がある。
- **直し方**: 左ナビの行き先に「お知らせ」を常設する（バッジ付き）。上のバーの扱いは今のままでよい。

### J-03 「担当が未定」を取り消しと同じ赤で描いている（S2、UI-12 の積み残し）

- **実測**: `src/web/ledger/Timetable.tsx:53` が `alert: 'bg-danger-soft border-danger'`、
  同 503 行が `担当が未定` を `text-danger` で描く。台帳の 3 件が赤い帯になっている。
- `packages/ui/src/theme.css:83` は `--color-danger` を「取消・警告・現在時刻の線・破壊的操作」と
  定義している。担当未定は失敗ではなく「これから決めること」なので、定義に反する。
- 同じ凡例の「ご来店なし」は失敗なので danger のままでよい。
- **直し方**: 担当未定を `--color-amber`（失敗ではない注意）へ。danger は取消と来店なしに限る。

## そのほか

### J-04 設定のグループ見出しがカードに接している（S2）

- **実測**: 「行き方のご案内」の見出しの top = 428.5px、その上のカードの bottom = 428.5px。
  **余白ゼロで接触**している。
- さらに、同じ「項目と値」の並びなのに、上の 4 行は枠のあるカード、下の 3 行は枠なしの素の行で、
  器の有無が揃っていない。
- **直し方**: グループを 1 つの部品（`<SettingGroup title>`）にまとめ、見出しの上余白を一律にする。

### 直っていることを確認したもの（再指摘しない）

- **UI-11**（設定の保存／変更を捨てる）: 実測で `保存` は bg `rgb(23,112,90)` の緑の塗り、
  `変更を捨てる` は 1px の枠を持ち、どちらも押せないときは opacity 0.4 + `cursor: not-allowed`。直っている。
- **UI-10**（空の状態）: 来店受付の空は横中央に見出し・理由・「＋ ご来店を受け付ける」が並ぶ。直っている。
- **UI-04**（サイドバーの幅の往復）: 幅の既定は**その画面を初めて開いたときだけ**当たる
  （`App.tsx:375`）。往復はしない。ただし初回は利用者が触らないうちに 216px → 76px と畳まれる。
  盤に幅が要るという判断は筋が通るので、defect とはしない。
