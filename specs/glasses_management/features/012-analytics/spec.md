# 012-analytics: 分析

- サービス: `glasses_management`
- ステータス: Approved

## 1. WHAT / WHY

**概要**: 朝礼と月次のふりかえりで使う 8 タブを出す（モックがあるのはトップ／予約数／担当者／お待ち時間／取り消しの 5 枚で、
残る「予約の入口」「来店回数」「ご来店の目的」も同じ型で作る。押しても何も出ないタブは壊れて見えるため出さないという選択は採らない）。
数字そのものより「何を、いつを基準に、どれだけの母数で数えたか」が画面の上で読めることを主眼にし、
根拠にできない数字（標本が少ない率・まだ集計できていない期間）は数字として出さない。

**ユーザーストーリー**:

- US-ANA-01: 店長として、朝礼で最初の 1 枚を開くために、前後 2 週間の入り具合と週ごとの数字が 1 画面で読める面がほしい。
- US-ANA-02: 店長として、その数字を人に説明するために、何をどう数えたかの定義が画面の上に書いてあってほしい。
- US-ANA-03: 店長として、比べたい相手を自分で決めるために、対象の期間と店舗を選んでから集計させたい。
- US-ANA-04: 店長として、お客様を待たせすぎていないか知るために、受付からご相談開始までの長さを目安と並べて見たい。
- US-ANA-05: 店長として、判断を誤らないために、標本が少ない率とまだ集計できていない期間は数字として見せないでほしい。
- US-ANA-06: 運営者として、他の会社・担当外の店舗の数字が 1 件も混ざらないことを保証したい。

**ユースケース**:

- UC-ANA-01: 店長は分析トップで前後 7 日の入り具合と、週ごとの件数を読むことができる。
- UC-ANA-02: 店長は対象の期間と店舗を選び、「適用」を押して集計をやり直させることができる。
- UC-ANA-03: 店長は予約数を「集計の種類」と「かぞえる日」の切り口を変えて数えることができる。
- UC-ANA-04: 店長は担当者ごとの件数と 90 日以内の再来を、1 つの並びで読むことができる。
- UC-ANA-05: 店長は受付からご相談開始までの中央値を、目安 8 分の線と並べて読むことができる。
- UC-ANA-06: 店長は取り消しを理由と出どころで 5 つに分けた積み上げと、期間のまとめで読むことができる。
- UC-ANA-07: システムは標本が閾値に満たない率を数字にせず伏せることができる。
- UC-ANA-08: システムは定休日の 0 件と、まだ集計できていない日とを分けて示すことができる。
- UC-ANA-09: システムは選択中の組織と店舗の外にある予約を、集計から外すことができる。
- UC-ANA-10: 店長は、予約の入口・来店回数・ご来店の目的の 3 つの切り口も、ほかのタブと同じ型の 1 枚として読むことができる。

**受け入れ基準**:

**スコープ外**: チェーン管理者が複数の店舗を並べて比べる面（役割は「店長」と「スタッフ（設定は見るだけ）」の 2 段しか持たず、
店舗をまたぐ読み方はヘッダーで店舗を切り替えて行う）。分析結果の書き出し・印刷・メール送信。
目安値そのものを画面から変える操作（目安は全店共通の固定値なので、変える操作はどの feature にも作らない）。
取り消しの登録・取消理由の入力（`009-change-and-cancel`）。来店工程の記録（`008-reception-and-walkin`）。
お知らせ・アラートの一覧とバッジ（`013-terminals-and-audit`）。

**決めたこと**（第2巡の検査で決着させた。根拠は承認済みモックと決定ブリーフ）:

- モックの無い 3 タブ（「予約の入口」「来店回数」「ご来店の目的」）も作る。タブが 8 つ描かれている以上、押して何も出ないタブは壊れて見える。作りは既存 5 枚と同じ型（グラフ 1 つ＋何をいつ基準に数えたかの 1 行＋まとめ 3 行）に揃える。
- 小標本抑制の閾値は 20 件。20 件に満たない担当の率は「—」にし、件数だけを出す（担当者別で 1 人あたり月 20 件を下回ると率が跳ねる）。
- まだ集計ができていない期間があるときは、期間セレクタの下に「〜日ぶんはまだ集計中です」の 1 行を出す。
- 取消率の分母は「その期間に来店予定だった予約の総数（取り消し・ご来店がなかったものを含む）」。いっぽう「予約数」には取り消した予約を含めない。率と件数で分母が同じだと「取り消しても予約数が減らない」ことになり、現場の感覚と合わない。
- 「1日あたり」の分母は営業日数（定休日・臨時休業を除く）。2026年8月は火曜（4・11・18・25）の 4 日を除く **27 日**なので、320 ÷ 27 = 11.851... → **11.9 件**である。暦日 31 を分母にする 10.3 件にも、26 日を分母にする 12.3 件にもならない。
- 目安の 3 つ（お待ち時間 8 分・取消率 10%・再来 90 日）は全店共通の固定値とし、画面から変える操作は作らない（設定の第 2 サイドバー 15 項目に目安を編集する行が 1 つも無い）。
- 件数 0 の担当の行は出す（その人が 0 件だったことが情報である）。受付 0 件の時間帯の棒は描かない（軸は残す）。
- 担当者の系列は `analytics_daily.dimension_label` の文字列（Unicode）順で安定して並べ、`unassigned`（担当が未定）だけを必ず最後に置く。表示時に staff マスターを読み直さない。
- 顧客未特定でも担当済みの完了来店は再来率の分母へ含め、分子は 0 とする。担当未定だけは率を出さない。
- 月途中の未来予約は月合計へ含めるが、営業状態行がまだ無い未来日は「1日あたり」の分子から外し、分母は `closed=0` の営業日数とする。
  保持削除はbackfill期間ではなく実行時のJST当日を基準にし、CronはKVのcursorで1起動3店舗ずつ続行する。
- グラフの系列は、塗りの色に加えて凡例の四角へ地模様（斜線・点）を入れ、系列名の文字を必ず添える。横軸の見出しを色で染め分けるだけにしない。
- 取り消しの内訳は `analytics_daily` の `metric='cancellations'`・`dimension='cancellation_category'` に日次保存する 5 つに分ける。キーは `customer` / `store` / `duplicate` / `no_show` / `web`、凡例の文字は CHANGE-CANCEL の 4 択と 1 字も違えず、「お客様のご都合」「店舗の都合」「予約の重複」「ご来店がなかった」「Webからの取消」とする。承認済みモックの 3 分類（「お客様都合」「無断キャンセル」「Webからの取消」）は、店舗都合と重複で取り消した件まで「お客様都合」に数えてしまうため採らない。棒の色は 3 系統のままでよいが、積み上げの本数は 5 本にする。画面要求は生表を読まない。
- モックの無い 3 タブは**案Bを正式仕様**とする。予約の入口は `source`（`phone` / `counter` / `web` / `walkin`）、来店回数は `visit_frequency`（`first` / `second` / `third_to_fifth` / `sixth_or_more`）、ご来店の目的は `purpose`（削除済み目的も当時の ID と表示名で保持）を、既存 5 枚と同じ 1 グラフ・定義 1 行・まとめ 3 行で表示する。これらが正式 3 モック相当の振る舞いである。
- 「名」（ANALYTICS-TOP の「88名」・ANALYTICS-COUNT の「414名」）は、**いまは出さない**。同行者を数える列も入力欄も工程も無く（`reservations` に人数の列が無く、店内・Web どちらの作成スキーマにも人数のフィールドが無く、予約の 5 工程に人数を伺う画面が 1 枚も無い）、いまの値は根拠を持てない。`analytics_daily` に `metric='guests'` の行を書かず、画面は件数だけを出す（`design/09-open-questions.md` の Q-11 のいまの前提）。答えが来たら、人数の列（`guest_count`、既定 1）と入力の欄を `006-booking-flow`（店内）・`008-reception-and-walkin`（ウォークイン）・`011-web-booking`（Web）に足したうえで戻す。決定ブリーフ §3 に無い列なので、そのときに人間の承認を取る。

## 2. HOW

**触るファイル**:

**データモデル差分**: `analytics_daily` を 1 表だけ新設する（`design/03-data-model.md` §11.4）。既存表への列追加は無い。
集計の元は `reservations` / `reservation_purposes` / `reservation_assignments` / `visit_events` / `staff` / `walk_ins` /
`store_business_hours` / `store_calendar_exceptions` で、画面からは触らず日次 upsert 経由で読む。
担当者名・目的名は `analytics_daily.dimension_label` に日次集計時点の表示名を保存し、無効化・改名後の過去レポートも生マスターを読まず表示する。
定休日も `value=0` の行を作り、行が無い日を「欠測」として区別する。物理指標・次元・ヒストグラムと再来率の定義は `design/03-data-model.md` §11.4 を単一の正とし、画面要求は `analytics_daily` だけを読む。

**却下した代替案**:

- 画面を開くたびに生の `reservations` を集計する: CPU 10ms とサブリクエスト上限に触れるため却下。日次集計表を読む。
- 待ち時間を平均で出す: 1 件の長い待ちに引きずられ、目安との比較が意味を失うため却下。中央値だけにする。
- 標本が少ない率を薄い色で出す: 色だけで伝えることになり、数字として引用されてしまうため却下。「—」にする。
- 取り消しの 5 分類を生表から読み出し時に組み立てる: 表示 API が期間ごとに生表を走査し、集計済み読取の境界を破るため却下。`analytics_daily` の `cancellation_category` 次元に保存する。
- 凡例をモックのまま「お客様都合」の 3 分類で出す: 店舗都合と重複で取り消した件が「お客様都合」に化け、事実と違う数字を店長が読むため却下。凡例の文字を CHANGE-CANCEL の 4 択に揃える。
- 欠測の日を 0 件の棒で描く: 定休日の 0 件と見分けがつかなくなるため却下（AC-ANA-15（前掲））。
- 期間や店舗を変えた瞬間に集計し直す: 指を滑らせるたびに叩くことになるため却下。「適用」を押したときだけ集計する。
