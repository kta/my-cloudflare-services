# 004-store-settings: 店舗の受付条件

- サービス: `glasses_management`
- ステータス: Approved

## 1. WHAT / WHY

**概要**: 店舗の情報・営業日・営業時間・スタッフと技能・設備と点検・ご来店の目的の 6 面を
店長が設定できるようにする。設定は左に分類、右にグループ表という読み方で 6 面を揃え、
保存が既にあるご予約に響く面では「保存する前に、いまの予約への影響を数えて見せる」という同じ型を使う。
保存を拒むのは**いま入っているご予約を壊す変更だけ**にし、今後の受付可能性が減るだけの変更（刻みが片付け時間より短い・
技能を外した結果その技能を持つ担当が 0 人になる・必要な資源を満たせない目的が出る・勤務時間が営業時間からはみ出す）は
警告を出したうえで通す。拒否だけにすると人員が抜けた日に何も保存できなくなるためである。
入力そのものを拒むときの文言は「〜のため保存できません。〜を直してください。」の 2 文に揃える。

**ユーザーストーリー**:

- US-SET-01: 店長として、お客様に見せる店名・道順・紹介文を 1 か所で直したい。ここが Web予約・確認メール・受付票の 3 か所に同時に効くため。
- US-SET-02: 店長として、閉店間際にお受けしたご予約を後からお断りせずに済むように、営業時間と臨時のお休みと受付を止める時間帯を決めて、本当に最後まで受けられる時刻まで確かめたい。
- US-SET-03: 店長として、誰がどの目的を受け持てるかを技能と勤務時間で決めたい。この並びがそのまま予約台帳の行になるため。
- US-SET-04: 店長として、お客様に取り消しのお電話を差し上げずに済むように、設備を点検で止めるとき、止めると困るご予約を保存の前に知りたい。
- US-SET-05: 店長として、お客様が選べる枠を黙って減らさないように、ご来店の目的の所要時間を変えるとき、受けられなくなる Web 枠を保存の前に知りたい。
- US-SET-06: スタッフとして、設定は見るだけにして、誤って店の受付条件を変えてしまわないようにしたい。

**ユースケース**:

- UC-SET-01: 店長は店舗の情報（店名・お客様に見せる店名・電話番号・住所・最寄り駅・出口と所要時間・駐車場）を直して保存できる。
- UC-SET-02: 店長はお客様に見せる紹介文を文字数を見ながら書き直し、200 文字以内で保存できる。
- UC-SET-03: 店長は通常の営業時間（開店・閉店・お昼の休憩）と曜日ごとの上書きを直して保存できる。
- UC-SET-04: 店長は受付を止める時間帯を足したり、既にある時間帯を直したりできる。
- UC-SET-05: 店長は予約の間隔（片付け時間・刻み・同じ時刻に受けられる件数）を決め、最後にお受けできる時刻を保存の前に確かめられる。
- UC-SET-06: 店長は営業日のカレンダーで臨時のお休みを入れたり営業日へ戻したりでき、店舗まるごとの受付も止められる。
- UC-SET-07: 店長はスタッフを選んで、できること（技能）を切り替えて保存できる。
- UC-SET-08: 店長はスタッフの曜日ごとの勤務時間を直して保存できる。
- UC-SET-09: 店長は設備を点検で止め、止めると影響するご予約を保存の前に数えて見られる。
- UC-SET-10: 店長はご来店の目的の所要時間・必要な技能・必要な設備・Web予約への公開を直し、受けられなくなる Web 枠を保存の前に数えて見られる。
- UC-SET-11: 店長は設定の切り替え（「いま使える」「Web予約に出す」）を指でも読み上げでも同じように扱え、いまどちらになっているかを文字でも読める。
- UC-SET-12: 店長はスタッフを新しく登録できる。退職したスタッフは行を消さず「いま使える」を切って残す。
- UC-SET-13: 店長は設備・場所を新しく登録できる。廃棄した設備も行を消さず「いま使える」を切って残す。
- UC-SET-14: 店長はご来店の目的を新しく登録し、一覧の並び順を決められる。使わなくなった目的も行を消さず「いま使える」を切って残す。

**受け入れ基準**:

- AC-SET-01: Given 業務画面を開いている, When 左の柱の「設定」を押して分類から「店舗の情報」を選ぶ, Then 見出しが「店舗の情報」になり、「お店の基本」と「行き方のご案内」のグループ表が並ぶ。
- AC-SET-02: Given 「店舗の情報」を開いている, When 店名と住所の 2 項目を直して「保存」を押す, Then 押す前は上の札が「未保存の変更 2件」で「保存」が押せる状態になっており、押したあとは読み上げに割り込まない知らせとして「保存しました」が 1 度だけ伝わって「未保存の変更」の札が消える。一部だけ保存できた状態は作らず（`db.batch()` で全部通すか全部落とす）、落ちたときは「保存できませんでした。入力はそのまま残っています。」と出して打ち込んだ値を保つ。
- AC-SET-03: Given 未保存の変更がある, When 「キャンセル」を押す, Then 値が編集前へ戻り、「未保存の変更」の札が消える。ここでの「キャンセル」は**編集の破棄**であって予約の取り消しではない。予約をやめることは全画面で「取り消し」と書き、「キャンセル」を予約の意味で使わない。
- AC-SET-04: Given 「お客様に見せる紹介文」を書き直している, When 200 文字ちょうどを入れて保存する, Then 「200文字／200文字まで」と出て保存でき、201 文字目を足すと「紹介文が 200 文字を超えているため保存できません。文字数を減らしてください。」と出て保存できない。
- AC-SET-05: Given 「営業時間」を開いている, When 閉店を開店と同じかそれより前の時刻にして「保存」を押す, Then 「閉店が開店より前のため保存できません。閉店の時刻を直してください。」と 2 文で出て保存されず、営業時間は元のままである。受付を止める時間帯が営業時間の外にはみ出したときも同じ型で拒む。
- AC-SET-06: Given 「営業時間」を開いている, When 「＋ 止める時間帯を足す」を押して名前と時間帯を入れて保存する, Then 「受付を止める時間帯」に行が 1 つ増える。
- AC-SET-07: Given 木曜日は 10:00–19:00 で、止める時間帯が「閉店前の片付け 18:40–19:00」、1件あたりの片付け時間が 10分、刻みが 30分ごと、最も短いご来店の目的が 20分である, When 「営業時間」の「予約の間隔」を見る, Then 「木曜日に最後にお受けできるのは 18:20 です。」と出る。この時刻は表示のための別計算ではなく、空き枠エンジンがその日に返す**最後の開始時刻そのもの**で、押せない時刻を案内しない。
- AC-SET-08: Given 「営業日」を開いている, When 2026年9月30日（水）の丸を押して保存する, Then その日が休みの見た目になり、「まとめて決める」の「臨時のお休み」に「9月30日（水）」が入る。
- AC-SET-09: Given 9月30日を臨時のお休みにしている, When もう一度その日の丸を押して保存する, Then その日が営業日へ戻り、「臨時のお休み」から消える。
- AC-SET-10: Given 「スタッフと技能」を開いている, When 左の一覧から「佐藤 美咲」を選ぶ, Then 右が「佐藤 美咲 の設定」になり、「できること（技能）」の「視力測定」「加工」「販売・受付」に ✓ が付いている。
- AC-SET-11: Given 「佐藤 美咲」を選んでいる, When 「フィッティング」の技能を押して保存する, Then 左の一覧の佐藤 美咲の技能に「フィッティング」が加わる。
- AC-SET-12: Given 「佐藤 美咲」の「勤務時間」の日曜日が「12:00–19:00」である, When 日曜日を「10:00–19:00」に直して保存し、画面を開き直す, Then 日曜日の欄が「10:00–19:00」になる。日曜の営業時間が 10:00–18:00 のときに 12:00–19:00 のような営業時間の外にはみ出す勤務を入れても保存は拒まず、「日曜日の勤務が営業時間（10:00–18:00）の外にはみ出しています。」と警告だけを出す。
- AC-SET-13: Given 「設備と点検」を開いている, When 「視力測定機 B」を選んで「いま使える」を切る, Then 「止めると影響するご予約　3件」が出て、山口 真央 様・川上 恵 様・佐々木 亮 様の 3 行が並び、上の札が赤くなる。保存しても割り当ては自動で付け替えず、外れた予約は「担当が未定」と同じ扱いで台帳に残す（自動で付け替えると、お客様に伝えた担当が黙って変わるため）。
- AC-SET-14: Given 「設備と点検」を開いている, When 影響するご予約が 0 件の設備を選んで「いま使える」を切る, Then 影響の一覧は出ず、上の札「未保存の変更 1件」は赤くならない。
- AC-SET-15: Given 「ご来店の目的」を開いている, When 「メガネを新しく作る」の所要時間を 50分から 60分に変える, Then 「50分から変更」の札が付き、「60分に延ばすと受けられなくなるWeb枠　2件」が出る。
- AC-SET-16: Given 「ご来店の目的」の一覧にある 6 件がすべて「公開しています」になっている, When 「修理・部品交換」を選んで「Web予約に出す」を切り、保存する, Then 一覧のその行の Web予約が「お店で受けるだけ」になり、「公開しています」の行が 5 件になる。
- AC-SET-17: Given スタッフの権限（中村 彩）で入っている, When 営業時間を直して「保存」を押す, Then 「この操作は店長だけができます」と出て、本文が「営業時間と定休日を変えられるのは 店長 だけです。中村 彩（スタッフ）の権限では保存できません。設定はまだ何も変わっていません。」になり、打ち込んだ 2 行は「下書きは残っています」の下にそのまま画面に残る。本文は `{対象}を変えられるのは 店長 だけです。{操作者}（{役割}）の権限では保存できません。{対象}はまだ何も変わっていません。` の型で、`{対象}` は第2サイドバーの項目名（`店舗の情報` / `営業日` / `営業時間` / `ご来店の目的` / `スタッフと技能` / `設備と点検`）、`{役割}` は「スタッフ」「店長」の 2 値を入れる。ご来店の目的で同じ面を出すと 1 文目と 3 文目の対象だけが差し替わる。
- AC-SET-18: Given 「設備と点検」で「視力測定機 B」を選んでいる, When 「いま使える」の切り替えを読み上げでたどる, Then 入と切を持つ切り替えとして状態つきで読まれ、画面にも「使えます」「止めています」の文字が出ていて、押せる範囲は行の高さぶん（44pt 以上）ある。飾りとして読み上げから隠したままにしない。
- AC-SET-19: Given 設定を直している, When 「未保存の変更 1件」の札や「止めると影響するご予約 3件」の件数が変わる, Then その変化は読み上げに割り込まない知らせとして 1 度だけ伝わり、接客中の読み上げを断ち切る警告にはしない。
- AC-SET-20: Given 「スタッフと技能」を「スタッフ 6名」で開いている, When 「＋ スタッフを足す」からお名前・ふりがな・できる役割・できること（技能）を入れて保存する, Then 一覧が「スタッフ 7名」になり、足した人が担当者別の台帳の行として並ぶ。既にいるスタッフの「いま使える」を切ると台帳の行から外れるが、その人が担当していた過去のご予約からは名前が消えない。
- AC-SET-21: Given 「設備と点検」を開いている, When 「＋ 設備を足す」から名前と種別（視力測定機／相談カウンター／加工台）を入れて保存する, Then 設備の一覧に 1 行増え、設備・場所別の台帳にその行が出る。
- AC-SET-22: Given 「ご来店の目的」を「ご来店の目的　6件」で開いている, When 「＋ 目的を足す」から目的の名前（店内）・お客様に見せる名前・所要時間・必要な技能・必要な設備を入れて保存する, Then 一覧が「ご来店の目的　7件」になり、その順のまま予約の工程 2 の札と Web 予約の目的の並びに出る。

**スコープ外**: Web予約の公開設定（SETTINGS-WEB は `011-web-booking`）、空き枠エンジン本体と予約台帳（`005-availability-and-ledger`）、
スタッフの PIN を作り直すことと端末の登録（`013-terminals-and-audit`）、設定変更の監査記録の閲覧（`013-terminals-and-audit`）、
第2サイドバーのうちモックが描いていない 8 項目（「予約のきまり」「受付できる時間」「お知らせ文」「（顧客台帳）項目」「注意ごと」「端末の登録」「PINと自動ロック」「通知・印刷」）。

**不明点**: なし（第2巡で全件決着した。決めた内容は上の受け入れ基準と下の HOW に書き込んである）。

**データモデル差分**: `store_business_hours` / `store_calendar_exceptions` / `store_slot_rules` / `store_blackout_windows` /
`store_settings_revision` / `staff` / `staff_skills` / `staff_weekly_shifts` / `staff_shifts` / `equipment` /
`equipment_maintenance` / `visit_purposes` / `purpose_requirements` の 13 表を新設し、
`stores` に `name_public`（お客様に見せる店名）/ `intro_text`（紹介文）/ `nearest_station` / `parking_note` /
`sort_order` / `updated_at` / `updated_by` の列を、`staff` に `role`（`manager` / `staff` の 2 値）・
`max_parallel_reservations`（既定 1・1〜5）・`pin_hash` を、`equipment` に `inactive_reason` を足す。
列名は `design/03-data-model.md` を正本とし、`design/04-api.md` §4.0 が名指しで禁じた別名
（`max_parallel` / `stopped_reason` / `public_name` / `intro`）を使わない。
`stores.sort_order` は `00_service-spec.md` / 05 / 06 / `011-web-booking` が既に使っているのに 03 §4.1 に列が無いので、
`store_blackout_windows` / `store_settings_revision` と同じく決定ブリーフ §3 に無い追加として人の承認を取る（規約 10）。

- **受付を止める時間帯は `store_blackout_windows` に 3 帯持つ**（朝の支度 10:00–10:15 / お昼 12:00–13:00 /
  閉店前の片付け 18:40–19:00）。`store_business_hours.break_*` の 1 帯では SETTINGS-HOURS の
  「＋ 止める時間帯を足す」が成立しない。お昼の帯は **12:00–13:00** とする
  （BOOK-01-DATETIME と WEB-03-DATETIME はどちらも 12:00・12:30 の枠を 1 つも出さず、満席の枠は出しているので
  「埋まっているから消えた」ではない。逆に LEDGER-STAFF と EX-OFFLINE は 13:00 に実際のご予約を 2 件置いている。
  SETTINGS-HOURS の「13:00–14:00」がモックの誤記である）。**この表は決定ブリーフ §3 に無いので、着手前に人の承認を取る（規約 10）。**
- **LEDGER-STAFF の灰色の帯（13:00–14:00）は店舗の停止帯ではなく担当の休憩**（`staff_shifts.kind='break'`）である。
  同じ時間に別の担当が接客しているので、店舗の停止帯とは別物として持つ。
- **勤務時間は曜日で編集し、`staff_weekly_shifts`（月〜日の 7 行）を正とする。** `staff_shifts` はそこから
  62 日先までを展開した結果で、保存時と日次 Cron の両方で展開する。日付行だけを持つと先週の編集が来月に効かない。
- **設定の楽観ロックは店舗単位の 1 版（`store_settings_revision`）にまとめる。** `version` を持たない 7 表を
  個別に版管理すると 1 画面の保存が 7 本の版比較になる。SETTINGS-* のどの面の「保存」もこの 1 版を条件に付け、
  ほかの端末が先に保存していたら 409 を返し、EX-CONFLICT と同じ型（相手が変えた項目の差分 ＋「取り直す」／「1項目ずつ選ぶ」）で
  見せて、打ち込んだ下書きは画面に残す。
- **版の条件は `db.batch()` の全文に配り、版を進める文をバッチの最後に置く。**
  D1 の `db.batch()` は 0 行しか当たらない `UPDATE` を「失敗」と見なさず、バッチを中断しない。
  そのため `UPDATE store_settings_revision ... AND version = ?` を 1 文目に置いても、後続の営業時間・スタッフ・設備の
  書き込みは commit されてしまい、「409 を返しながら相手の変更を黙って巻き戻す」ことになる（規約 14 が成立しない）。
  各表の書き込みは `... WHERE EXISTS (SELECT 1 FROM store_settings_revision WHERE store_id = ?1 AND version = ?2)` でガードし、
  `version` を +1 する `UPDATE` を**最後の文**に置く。バッチ全体が 1 トランザクションなので全文が同じ版を見て、
  **全部通るか 1 行も変わらないか**のどちらかになる。409 の判定は最後の文の `meta.changes === 0` で行う。
- **`staff.max_parallel_reservations`（1〜5）・`equipment.capacity`（1〜10）・`store_slot_rules.max_parallel`（同時受付 3 件）は、
  枠の占有を数える側で上限として効かせる。** 枠 1 本 = 1 行の一意 index で二重確保を止めると、この 3 つの設定の実効値が
  1 に固定され、画面で編集できるのに効かない設定になる。占有は `reservation_slot_locks` への**上限つきの条件付き INSERT**
  （`005-availability-and-ledger` の HOW）で数え、ここで設定した値をそのまま上限として渡す。
- **予約の刻みと片付けは `store_slot_rules` に持つ**（30 分刻み・片付け 10 分・同時受付 3 件）。
  曜日ごとの上書きは 3 種（定休 / 時間差し替え / 通常どおり）を `store_calendar_exceptions` で持つ。
- **目的の必要資源（`purpose_requirements`）は技能 1 つ＋設備 2 つまで**持てる。
  `kind='skill'` が取る技能の語彙は SETTINGS-STAFF の「できること（技能）」と同じ 6 つ
  （視力測定 / 加工 / 販売・受付 / フィッティング / コンタクトの相談 / 修理・部品交換）だけである。
- **ご来店の目的の seed は SETTINGS-PURPOSE の 6 件**とする。メガネを新しく作る 60 / 今のメガネを調整したい 20 /
  できあがりを受け取る 20 / 修理・部品交換 30（Web 非公開）/ コンタクトの相談 40 / 視力測定だけ 30。
  決定ブリーフ §11 の「フィッティング(30)」は**目的ではなく技能**なので目的の seed には入れない。
  お客様に見せる名前（`name_public`）は SETTINGS-PURPOSE の「お客様に見せる名前」列を正本にする
  （新しいメガネを作る / かけ具合の調整 / できあがりの受け取り / 修理・部品の交換 / コンタクトのご相談 / 視力測定）。
  Web に公開するかどうかは `is_web_published` 単独で判定し、seed では 5 件が公開・修理・部品交換だけが「お店で受けるだけ」になる。
- **設備・場所の seed は 7 件**（視力測定機 A / B・検査室 1 ＝ `measure`、相談カウンター 1 / 2・フィッティング台 ＝ `counter`、
  加工室 ＝ `workbench`）。フィッティング台も `is_active='1'` の間は設備軸の台帳に行として出す。
- **スタッフの seed は 6 名**（佐藤 美咲 / 高橋 健 / 中村 彩 / 小林 学 / 渡辺 由紀 / **山田 大輔（店長）**）。
  決定ブリーフ §11 の「高橋 慎輔（店長）」は誤りで、SETTINGS-STAFF の一覧が正しい。
  役割は「店長」と「スタッフ（設定は見るだけ）」の 2 段だけを持ち、チェーン管理者・監査担当を独立した役割にはしない。
- **スタッフごとの暗証番号（`staff.pin_hash`）は端末の暗証番号（`terminals.pin_hash`）とは別に持つ。**
  ハッシュには `AUTH_PEPPER` を使う。

**却下した代替案**:

- 保存してから影響を出す: 取り消しの手間が客に及ぶため却下。保存の前に読み取り専用で試算する。
- 「最後にお受けできる時刻」を列として保存する: 営業時間・止める時間帯・刻みからの派生値なので却下。毎回算出する。
- 設定 6 面を 6 ルートに分ける: 分類の柱が全画面で同一なので却下。`/settings?section=...` の 1 ルートにする。
- 「相談カウンター 1・2」を 1 行 1 レコードで持つ: 台帳の行と 1 対 1 にならないため却下。1 台 1 行にして設定画面の表示側でまとめる。
- 影響の試算を画面ごとに別の API にする: 3 画面が同じ器を使うため却下。1 本の試算 API に種別を持たせる。
