## 1. 要件定義書の目的と読み方

### 1.1 目的

本書は、EYEX予約の**業務要件（WHY / WHAT）**を、実装・テスト・画面設計に一貫して利用できる粒度で定義する。
設計の判断根拠は本書を正とし、画面の見た目と状態は `design/`、実装方法と作業分解は WHAT 承認後に本書の HOW / TASKS へ追記する。

### 1.2 用語

| 用語 | 本書での意味 |
| --- | --- |
| 選択中店舗 | ヘッダーで明示的に選択され、予約・台帳・検索・設定の操作対象となる1店舗。 |
| 店舗横断 | 権限を持つ利用者が、顧客の来店・購入・接客履歴を複数店舗にわたり参照できること。空き枠の横断検索・比較を意味しない。 |
| ウォークイン | 予約なしで来店したお客様。顧客未特定のまま受付・接客を開始できる。 |
| 受付セッション | 電話受付を開始してから、予約確定または破棄するまでの記録単位。予約IDを持たない破棄受付にも存在する。 |
| 完全共有iPad | レジ横などに設置し、日常業務では個人ログインを求めない店舗共用端末。 |
| 注意事項 | 接客で必要な事実、根拠、推奨対応を記録する情報。人格評価・憶測・差別につながる記録は含めない。 |

## 2. 事業背景・プロダクト定義

### 2.1 背景

眼鏡店の予約業務は、電話での聞き取り、来店目的に応じた技能・設備の空き確認、既存顧客の度数・調整履歴・引き継ぎ事項の確認を短時間で同時に行う必要がある。
予約、顧客情報、店頭受付が分断されると、聞き漏れ、ウォークインの記録漏れ、二重確認、担当者不在時の接客品質低下が起きる。複数店舗のチェーンでは、共通ルールと店舗固有の営業条件を両立させながら、安全に運用する必要がある。

### 2.2 プロダクト定義

**EYEX予約は、複数店舗を持つ眼鏡店が、予約・来店受付・顧客情報を一つの現場導線で扱い、スタッフが次の接客に必要な事実をすぐ確認できるようにするサービス**である。

主利用環境は横向きiPadの店舗業務画面、顧客向け入口はスマートフォンWeb予約とする。TORETAからは「会話順の入力」「予約入口の一元化」「台帳で現場を把握する」という原則だけを参照し、商標、画面資産、文言、配色は複製しない。

### 2.3 今回の到達点

- 電話予約を、電話で尋ねる順番どおりに確実に登録できる。
- 予約・ウォークイン・Web予約を、選択中店舗の同一台帳と来店進捗で把握できる。
- 顧客を特定した時点で、現在度数、最新メモ、保有メガネ、許可された履歴・注意事項を接客中に確認できる。
- 店舗ごとの受付条件とWeb予約公開条件を、影響確認・公開・監査まで含めて安全に管理できる。

### 2.4 フェーズ境界

本フェーズは予約・来店受付・既存の顧客事実の参照と記録を対象とする。次は対象外であり、要件・画面・データモデルへ混在させない。

- 商品SKU、レンズ互換性、在庫、保証のヘルプデスク
- AIによる商品推薦、クロスセル・アップセル、スタッフ向け提案生成
- 購入後の買い替え・保証・メンテナンスの個別最適化フォロー

これらは「店員が全商品と全顧客を覚えている状態」を目指す第3フェーズの検討対象であり、将来参照のために本フェーズの顧客データを必要最小限・事実ベースで整備するが、AI推論や提案機能は実装しない。

## 3. ターゲット・ペイン・提供価値

| ターゲット | 実際の業務場面 | 現在のペイン | EYEX予約が提供する価値 | 主な要求群 |
| --- | --- | --- | --- | --- |
| 店舗スタッフ | 電話を受けながら予約を取る | 聞く順番や必要項目が属人的で、枠の競合や聞き漏れが起きる | 読み上げ可能な一問ずつの入力と、目的選択後の再検証 | B, C, D, F, Q |
| 店舗スタッフ | 予約なしのお客様を受け入れる | 顧客情報の確認に時間がかかり、後入力の記録が消えやすい | 顧客未特定でも受付を始め、後から安全に関連付ける | C, E, I |
| 店長 | 当日の現場を判断する | 予約元・待機・担当・設備の状態が別々で、遅延に気づきにくい | 一つの台帳、現在時刻の縦線、来店進捗、運用警告 | E, J, R |
| 複数店舗担当者 | 店舗をまたいで業務する | 他店の予約情報を不用意に見たり、誤った店舗へ登録する危険がある | ヘッダーで明示切替し、選択店舗だけで予約操作する | G, N |
| チェーン／店舗管理者 | 店舗条件・Web公開を変更する | 共通ルールと店舗事情が混ざり、既存予約への影響を見落とす | 共通値・上書き、下書き、影響確認、公開、監査 | I, K, M, N, O |
| 監査担当者 | 録音・重要操作を確認する | いつ、誰が、どの端末で何をしたか追いにくい | 受付セッション単位の録音、保持期限、保全、追記型監査 | D, M, N |
| 予約する顧客 | スマートフォンから予約する | 目的に合わない枠を選びやすく、完了・変更方法が分かりにくい | 店舗・目的・日時・本人情報を一問ずつ確定する導線 | H, K, P |

### 3.1 解くべきペインの優先順位

1. **予約を正しく受ける**: 電話・店頭・Webの入口が違っても、予約枠・来店目的・担当資源を矛盾なく扱う。
2. **次の接客を迷わせない**: 顧客が確定したら、履歴を探す前に現在の接客に必要な事実を表示する。
3. **現場を止めない**: ウォークイン、通信失敗、枠競合、担当変更でも、入力済み情報と接客の継続性を守る。
4. **チェーン運用を壊さない**: 店舗境界、共有端末、権限、設定公開、監査を初期設計に含める。

## 5. 対象範囲と業務境界

### 5.1 対象業務

| 業務 | 開始条件 | 完了条件 | 主な例外 |
| --- | --- | --- | --- |
| 電話・店頭予約 | スタッフが新規予約を開始する | 予約確定、または受付セッションを破棄する | 枠競合、録音失敗、通信失敗、顧客未特定 |
| ウォークイン受付 | 予約なしのお客様が来店する | 来店進捗を記録し、顧客関連付けまたは未登録退店を保存する | 顧客情報は後入力、担当・設備が未確定 |
| 予約検索・変更・取消 | 氏名・電話番号・予約番号などで対象を特定する | 変更、取消、または対象確認を完了する | 変更先枠の競合、録音の保存状態 |
| 顧客参照 | 顧客を特定する | 当日の接客に必要な事実を確認する | 権限外情報は存在も表示しない |
| 店舗切替 | 権限者がヘッダーで切替を開始する | 切替先店舗の業務画面を開く | 未保存入力、権限外店舗 |
| Web予約 | 顧客が店舗ポータルまたは店舗専用URLを開く | 予約番号を表示して完了する | 非公開、満席、本人確認失敗、確定結果不明 |
| 設定管理 | 管理者が設定を編集する | 影響確認済みの版を公開、または下書き保存する | 共通値との競合、部分失敗、未来予約との矛盾 |
| 分析・監査 | 権限者が期間と店舗を選ぶ | 指標または監査対象を確認する | 小標本抑制、欠損、権限外データ |

### 5.2 店舗境界の原則

- 予約・空き枠・台帳・受付履歴・Web予約設定は、常に選択中店舗だけを操作対象とする。
- 他店舗の空き枠を横断検索、一覧比較、候補提示、予約入力してはならない。
- 他店舗の予約を作成・変更する場合は、先にヘッダーで当該店舗へ明示的に切り替える。
- 顧客履歴はロールと担当店舗の権限がある範囲だけを横断参照できる。権限外情報は本文・件数・存在標識を表示しない。

### 5.3 非対象

本フェーズの非対象は「スコープ外」に列挙する。特に第3フェーズのAI商品提案領域は、予約・顧客参照の受入基準へ追加しない。

## 7. 詳細機能要件（ユースケース）

**概要**:

複数店舗を持つ眼鏡店チェーン向けに、横向きiPadを主利用環境とする店舗予約・顧客管理と、
同じ空き枠を利用する顧客向けWeb予約を提供する。TORETAの会話順入力、予約と顧客台帳の連動、
予約入口の一元化を、眼鏡店の来店目的、技能、設備、所要時間へ翻訳する。

**ユーザーストーリー**:

- US-EYEX-01: 店舗スタッフとして、電話中に画面の質問を読み上げながら予約を登録したい。
- US-EYEX-02: 店舗スタッフとして、電話番号の入力途中で既存顧客を特定し、過去の接客情報を確認したい。
- US-EYEX-03: 店舗スタッフとして、予約内容を復唱した記録を予約へ関連付け、聞き間違いを確認できるようにしたい。
- US-EYEX-04: 店舗スタッフとして、トップから新規予約、予約変更、履歴、検索、顧客台帳へすぐ移動したい。
- US-EYEX-05: チェーンスタッフとして、権限の範囲内で店舗をまたぐ顧客履歴を確認したい。
- US-EYEX-06: 顧客として、希望店舗、来店目的、日時を選び、Webから予約したい。
- US-EYEX-07: 店舗スタッフとして、予約なしの来店者をすぐ受け付け、顧客情報を接客中または退店後に関連付けたい。
- US-EYEX-08: 店舗スタッフとして、予約受付時のiPad録音を予約詳細から確認したい。
- US-EYEX-09: 複数店舗を担当するスタッフとして、明示的に店舗を切り替え、選択した店舗の予約業務を行いたい。
- US-EYEX-10: エリア責任者として、権限の範囲内で店舗を切り替え、各店舗の予約状況と運用上の警告を確認したい。
- US-EYEX-11: 顧客として、スマートフォンから店舗・来店目的・日時・本人情報を入力し、迷わず予約を完了したい。
- US-EYEX-12: 店舗管理者として、来店目的、所要時間、必要技能・設備、受付可能時間を店舗ごとに設定したい。
- US-EYEX-13: チェーン管理者として、全店共通値と店舗別上書きを安全に管理したい。
- US-EYEX-14: 店長として、予約数だけでなく来店、待ち時間、所要時間、キャンセルの状況から現場改善点を把握したい。
- US-EYEX-15: 監査担当者として、音声の保存・再生・削除と重要情報の変更履歴を追跡したい。
- US-EYEX-16: 店舗管理者として、店舗ごとにWeb予約の公開範囲と受付ルールを設定したい。
- US-EYEX-17: 店舗管理者として、来店目的の顧客向け文言、初期所要時間、必要技能・設備を初期値から編集したい。
- US-EYEX-18: 店舗スタッフとして、個人端末とレジ横の完全共有iPadのどちらからでも日常業務を行いたい。
- US-EYEX-19: チェーン管理者として、注意事項の閲覧・登録・公開・改訂権限を組織共通または店舗別に設定したい。

### 1.1 ユースケース一覧

#### A. ホーム・共通ナビゲーション

- UC-EYEX-001: スタッフはホームから新規予約を開始できる。

- UC-EYEX-152: 管理者は共有iPadの無操作ロック時間を組織既定値または店舗上書きとして設定できる。
- UC-EYEX-153: 管理者は成立予約と破棄受付の録音保存期間を最低保証未満にできない範囲で設定できる。
- UC-EYEX-154: 店舗管理者以上は録音保全一覧から理由付き保全・解除、保存・削除失敗、再試行結果を確認できる。
- UC-EYEX-155: 監査担当者は権限内の監査イベントを期間、店舗、操作、主体種別、対象で検索し、変更前後と相関IDを確認できる。
- UC-EYEX-156: システムは監査イベントを追記専用として扱い、監査記録の書き込みに失敗した管理操作を成立させない。
- UC-EYEX-157: 完全共有iPadはバックグラウンド移行、画面非表示、無操作タイムアウト時に顧客情報を直ちに隠せる。
- UC-EYEX-158: 共有セッション失効後の端末は、未送信データを含めて業務画面へ復帰せず再登録を要求される。

#### O. 設定公開・継承・復旧

- UC-EYEX-159: 管理者は設定の下書き、確認待ち、公開予約、公開中、受付停止を状態として、競合・失敗を状態とは別の警告として確認できる。
- UC-EYEX-160: 管理者は全店共通値と店舗上書きの差分を確認し、店舗上書きを解除して共通値へ戻せる。
- UC-EYEX-161: 管理者は公開予約の実行前に再検証し、公開予定を取消または変更できる。
- UC-EYEX-162: 管理者は設定公開後に版ID、対象店舗、反映件数、失敗件数、Web枠と台帳への反映結果を確認できる。
- UC-EYEX-163: 管理者は部分失敗した店舗だけを再試行し、成功済み店舗へ重複適用しない。
- UC-EYEX-164: 管理者は版履歴の差分を確認し、旧版を新しい下書きとして復元して影響確認後に公開できる。
- UC-EYEX-165: 管理者は設定変更で競合する未来予約を一覧化し、代替資源割当、例外維持、顧客連絡を記録して再検証できる。
- UC-EYEX-166: システムは公開開始・終了、予約可能日数、直前受付期限をJSTで評価し、境界時刻を一意に判定できる。

#### P. Web予約の入口・変更・回復

- UC-EYEX-167: 顧客は全店ポータルから店舗検索・店舗詳細を経て予約を始めるか、店舗専用URLから選択済み店舗で始められる。
- UC-EYEX-168: 顧客は非公開、受付停止、該当店舗なしの場合に理由と店舗への連絡方法を確認できる。
- UC-EYEX-169: 顧客は本人確認コードの送信、入力、再送、期限切れ、試行上限を安全に処理できる。
- UC-EYEX-170: 顧客は変更・取消期限内に予約内容を変更または取り消し、期限後は店舗連絡先を確認できる。
- UC-EYEX-171: 顧客は予約確定結果が不明な場合、二重作成せず予約番号または本人確認で成立状況を照会できる。

#### Q. 同時編集・通信障害・状態回復

- UC-EYEX-172: 複数端末が同じ予約、顧客、ウォークイン、注意事項、設定を更新した場合、古い版の上書きを拒否して最新差分を表示できる。
- UC-EYEX-173: スタッフは競合時に最新状態を確認し、自分の入力を破棄または最新状態へ再適用できる。
- UC-EYEX-174: システムは予約登録・変更・取消・録音アップロードの再送を冪等に処理できる。
- UC-EYEX-175: 一時通信失敗時の予約入力は端末・店舗・受付セッションに限定して保持し、共有セッション失効または保持期限到来時に破棄できる。
- UC-EYEX-176: 録音は権限確認、録音、停止、アップロード、保存済み、失敗、保全、削除済みの状態を持ち、予約状態とは独立して遷移できる。
- UC-EYEX-177: マイク権限拒否または録音失敗時、スタッフは録音できない状態を確認し、店舗運用で許可される場合だけ録音なしで予約を続けられる。

#### R. 通知・分析・顧客訂正

- UC-EYEX-178: スタッフはお知らせとアラートを一覧・詳細で確認し、既読と対応済みを区別できる。
- UC-EYEX-179: 管理者は待ち時間、録音保存失敗、設定矛盾などの警告条件と通知先を設定できる。
- UC-EYEX-180: システムは分析の小標本を組織設定の閾値で抑制し、抑制後の値から個人を逆算できないよう関連内訳も抑制できる。
- UC-EYEX-181: 権限者は顧客の重複候補を比較し、自動統合せず、統合または誤関連解除の影響と監査履歴を確認できる。

## 8. 受入基準

以下の受入基準は、承認後に各項目をちょうど1本のE2Eテストへ対応付ける。実装の完了は、画面が見えることではなく、該当する業務上の結果と例外時の回復を満たすこととする。

- AC-EYEX-01: Given トップ画面 When スタッフが新しい予約を取る Then 日、時間、来店目的、お客様情報、復唱するの順で予約入力が始まる。
- AC-EYEX-02: Given 予約入力中 When 各工程を表示する Then スタッフが電話口でそのまま読み上げられる質問文が主見出しに表示される。
- AC-EYEX-03: Given お客様情報工程 When 電話番号を途中まで入力する Then 一致する既存顧客候補が氏名、電話番号、主利用店舗、来店回数付きで表示される。
- AC-EYEX-04: Given 複数の顧客候補 When スタッフが1人を選ぶ Then 右側に店舗横断の来店履歴、接客メモ、根拠付き注意事項が表示される。
- AC-EYEX-05: Given 予約入力を開始 When マイク利用が許可されている Then 録音中であることを常時表示せず、予約入力に必要な領域を優先する。
- AC-EYEX-06: Given 復唱工程 When 必須情報が揃っている Then 日時、店舗、来店目的、所要時間、氏名、電話番号を含む読み上げ文が表示される。
- AC-EYEX-07: Given 復唱中 When 画面を表示する Then スタッフが復唱後に予約を確定でき、確定後に録音の保存状態を予約詳細または受付履歴で確認できる。
- AC-EYEX-08: Given 予約確定直前 When 予約枠が競合した Then 予約を作成せず、入力内容を保持して代替時間を提示する。
- AC-EYEX-09: Given トップ画面 When 横向きiPadで表示する Then 新規予約と予約変更が主操作、履歴・検索・顧客台帳が副操作、日付ストリップが下部に表示される。
- AC-EYEX-10: Given 既存顧客 When 別店舗で予約または接客する Then 許可されたスタッフはチェーン共通の顧客履歴を確認できる。
- AC-EYEX-11: Given 予約なしの来店者 When スタッフがウォークイン受付する Then 仮識別子と顧客未登録状態で台帳・来店受付へ表示され、接客を開始できる。
- AC-EYEX-12: Given 顧客未登録のウォークイン When スタッフが後入力を開く Then 氏名・電話番号による既存顧客検索または新規顧客登録を選択できる。
- AC-EYEX-13: Given 当日の予約台帳 When 現在時刻が予約時間帯内にある Then `現在 HH:mm` を持つ縦線が時刻グリッドの該当位置に表示される。
- AC-EYEX-14: Given 予約検索 When スタッフが氏名または電話番号を入力する Then 正規化された検索条件に一致する予約が表示される。
- AC-EYEX-15: Given iPad録音がある予約 When 許可されたスタッフが予約詳細を開く Then 録音日時・録音者・長さを確認し、再生・一時停止・シークできる。
- AC-EYEX-16: Given 既存顧客 When 顧客台帳を開く Then 現在の度数、最新メモ、保有メガネ、注意事項が履歴より先に表示される。
- AC-EYEX-17: Given ウォークインの仮識別子 When スタッフが既存顧客を関連付ける Then 来店・接客記録がその顧客から参照でき、実行者・日時・変更前後が監査履歴に残る。
- AC-EYEX-18: Given 顧客未登録のウォークイン When 顧客を登録せず退店する Then 来店・接客履歴は削除されず未登録状態で検索できる。
- AC-EYEX-19: Given 過去日または未来日の予約台帳 When 表示する Then 現在時刻ラインは表示されない。
- AC-EYEX-20: Given 電話番号検索 When ハイフン、空白、全角・半角が異なる番号を入力する Then 正規化後に同じ番号の予約・顧客候補が表示される。
- AC-EYEX-21: Given 氏名検索 When 氏名または氏名かなの一部を入力する Then 一致候補が表示され、スタッフが選択するまで対象は確定しない。
- AC-EYEX-22: Given 予約変更 When 新しい枠が競合する Then 元の予約を保持したまま変更を中止し、代替枠を提示する。
- AC-EYEX-23: Given 予約取消 When スタッフが取消を実行する Then 理由の入力と確認を求め、実行者・日時・変更前内容を監査履歴に残す。
- AC-EYEX-24: Given 顧客台帳 When 現在度数と過去度数がある Then 現在値と過去値が別領域に表示され、測定日・店舗・記録者を確認できる。
- AC-EYEX-25: Given 来店受付済みのお客様 When 工程を開始・完了・変更する Then 担当者、時刻、設備、引き継ぎ内容が記録され、店内進捗へ反映される。
- AC-EYEX-26: Given 来店中のお客様 When 待機時間が店舗設定の閾値を超える Then 対象者と次の対応が色だけに依存しない警告で表示される。
- AC-EYEX-27: Given 複数店舗への権限があるスタッフ When ヘッダーの店舗名を押す Then 店舗名、営業状態、運用警告を持つ切替候補が表示され、他店舗の空き枠は表示されない。
- AC-EYEX-28: Given 店舗Aを選択中 When スタッフが店舗Bへ切り替える Then 店舗Bのホームへ移動し、全スタッフ画面のヘッダーに店舗Bが表示される。
- AC-EYEX-29: Given 未保存の予約入力がある When スタッフが店舗切替を実行する Then 切替を中断し、現在店舗で入力を続けるか破棄するかを求める。
- AC-EYEX-30: Given 店舗を切り替えた When 切替先の予約画面を開く Then 切替元の検索条件、選択予約、入力内容、空き枠は持ち越されない。
- AC-EYEX-31: Given 店舗Aを選択中 When 予約枠を検索する Then 店舗Aの空き枠だけが表示され、店舗Bの枠を検索・入力できない。
- AC-EYEX-32: Given 顧客向けWeb予約 When 顧客が開始する Then 来店目的、日時、お客様情報、確認、完了の順に一問ずつ表示される。
- AC-EYEX-33: Given Web予約の全工程 When 画面を表示する Then 選択店舗と選択済みの来店目的・日時を確認できる。
- AC-EYEX-34: Given 来店目的工程 When 顧客が目的を選ぶ Then 顧客向けの説明と標準所要時間が表示される。
- AC-EYEX-35: Given 日時工程 When 空き枠を表示する Then 選択店舗かつ選択目的を受け付けられる日時だけが表示される。
- AC-EYEX-36: Given 選択店舗が満席 When 日時工程を表示する Then 同じ店舗の前後時刻または別日を提示し、他店舗の枠を混在させない。
- AC-EYEX-37: Given 予約確認工程 When 顧客が確定する Then 店舗、来店目的、日時、所要時間、氏名、連絡先、同意事項を確認できる。
- AC-EYEX-38: Given 顧客が予約確定を複数回実行する When 同じ確定操作として処理する Then 予約は一件だけ作成される。
- AC-EYEX-39: Given Web予約が成立する When 完了画面を表示する Then 予約番号、予約内容、変更・取消方法、店舗連絡先が表示される。
- AC-EYEX-40: Given 店舗管理者が設定ガイドを開始する When 工程を進める Then 店舗と営業時間、来店目的、スタッフと技能、設備と点検、Web予約公開、影響確認と公開の順に表示される。
- AC-EYEX-41: Given 設定ガイド When 任意の工程を表示する Then 完了済み、編集中、未完了の工程が色だけに依存せず左側に表示される。
- AC-EYEX-42: Given 来店目的を編集する When 顧客向け表示名と所要時間を入力する Then Web予約での表示内容を同じ画面で確認できる。
- AC-EYEX-43: Given スタッフと技能を設定する When 技能を選択する Then その技能を必要とする来店目的と予約枠への影響を確認できる。
- AC-EYEX-44: Given 設備と点検を設定する When 設備停止期間を入力する Then 影響を受ける公開枠と既存予約を確認できる。
- AC-EYEX-45: Given 設定変更が下書き状態 When 管理者が画面を離れる Then 下書きの保存状態と最終保存時刻を確認できる。
- AC-EYEX-46: Given 設定の公開前 When 影響確認工程を開く Then 既存予約の競合、Web公開枠、技能不足、設備不足が表示される。
- AC-EYEX-47: Given 日常的な設定修正 When 管理者が設定一覧を開く Then ガイドを最初から進めず対象設定へ直接移動できる。
- AC-EYEX-48: Given 全店共通設定と店舗上書きがある When 設定内容を表示する Then 適用元と上書き値を区別して確認できる。
- AC-EYEX-49: Given 分析画面 When 利用者が指標を選択する Then 対象期間、JST基準、最終更新時刻、対象件数、指標定義が表示される。
- AC-EYEX-50: Given 待ち時間指標 When 時間帯を選択する Then 受付から接客開始までの分布と関連工程を確認できる。
- AC-EYEX-51: Given 目標を超えた指標 When 詳細を表示する Then 原因を断定せず、根拠件数と確認対象を持つ原因候補が表示される。
- AC-EYEX-52: Given 比較可能な期間 When 利用者が分析する Then 現在値、比較期間との差、店舗目標を同じ単位で確認できる。
- AC-EYEX-53: Given 集計対象が少ない When 分析を表示する Then 個人特定につながる内訳を表示せず、小標本であることを示す。
- AC-EYEX-54: Given 集計データに欠損がある When 指標を表示する Then 除外件数、除外理由、解釈上の注意を確認できる。
- AC-EYEX-55: Given 複数店舗への権限がある When 店舗を切り替える Then 選択店舗だけの分析へ切り替わり、他店舗の明細を混在させない。
- AC-EYEX-56: Given 受付履歴 When 当日の履歴を表示する Then 予約受付、変更、取消、ウォークイン受付が発生日時の降順で表示される。
- AC-EYEX-57: Given 受付履歴 When 氏名、電話番号、予約番号を入力する Then 一致する受付イベントが表示される。
- AC-EYEX-58: Given 受付履歴 When 受付経路、操作種別、要確認状態で絞り込む Then 条件に一致するイベントだけが表示される。
- AC-EYEX-59: Given 受付イベント When スタッフが選択する Then 一覧を維持したまま予約内容、顧客、受付者、変更履歴が詳細に表示される。
- AC-EYEX-60: Given iPad録音がある電話受付 When 許可されたスタッフがイベントを選択する Then 録音情報と再生操作が表示される。
- AC-EYEX-61: Given 要確認フィルターを解除する When 履歴を表示する Then 問題のないイベントを含む全受付履歴が表示される。
- AC-EYEX-62: Given 店舗Aを選択中 When 受付履歴を開く Then 店舗Aのイベントだけが表示され、店舗Bのイベントを混在させない。
- AC-EYEX-63: Given Web予約設定 When 店舗管理者が開く Then 公開状態、公開期間、公開する来店目的、受付時間、予約可能日数、直前受付期限が表示される。
- AC-EYEX-64: Given Web予約が非公開 When 公開日時を指定して保存する Then 指定日時までは予約を受け付けず、指定日時以降に公開される。
- AC-EYEX-65: Given Web予約が公開中 When 受付停止する Then 新しいWeb予約だけを停止し、既存予約を維持する。
- AC-EYEX-66: Given Web予約設定を公開する前 When 影響確認を行う Then 公開予定枠数、営業時間外、技能不足、設備不足、既存予約との競合が表示される。
- AC-EYEX-67: Given 来店目的設定 When 顧客向け文言を編集する Then Web予約の質問、選択肢、説明、所要時間のプレビューが更新される。
- AC-EYEX-68: Given 新規店舗 When 来店目的設定を開始する Then 標準テンプレートの名称、文言、所要時間、必要技能、設備、Web公開初期値が表示される。
- AC-EYEX-69: Given 全店共通値を店舗で変更する When 保存する Then 店舗別上書きとして記録され、適用元と変更項目が表示される。
- AC-EYEX-70: Given 公開中の来店目的 When 非公開へ変更する Then 新規選択肢から除外されるが、既存予約と履歴は維持される。
- AC-EYEX-71: Given Web予約設定 When 店舗情報を編集する Then 顧客向けページの店舗名、アクセス、電話番号、注意事項を同じ画面でプレビューできる。
- AC-EYEX-72: Given SP幅で設定ガイドを表示する When 任意の工程を開く Then 6工程すべてが丸と線でヘッダー直下に固定表示され、横スクロールを必要としない。
- AC-EYEX-73: Given SP幅の工程表示 When 現在工程を表示する Then 現在工程番号、全6工程、残り工程数、完了・現在・未完了状態が色だけに依存せず表示される。

## 10. 確定済みの業務判断

- 画面設計は全対象について承認済み。
- Web予約の公開範囲と来店目的の初期値は店舗設定から変更可能にする。
- 成立予約の録音は最低30日、破棄された予約受付の録音は最低24時間保持する。これは最低保持の保証であり、削除日の保証ではない。
- 録音は選択中店舗の全スタッフが再生でき、店舗管理者以上が理由付きで保全・解除できる。ダウンロード機能は提供しない。
- 顧客向けの録音同意フローは設けない。録音対象はiPad環境マイクが取得する店員の復唱であり、電話回線を直接録音しない。
- 利用主体は個人アカウントと完全共有iPadの2種類とし、完全共有モードの日常操作では個人特定を必須にしない。
- 注意事項権限は設定画面で組織共通値と店舗上書きを管理し、完全共有モードの管理操作には管理者の個人認証を必須とする。
